# 메시지

## 대화와 전송

고객지원은 회원과 관리자, 가게 문의는 회원과 해당 가게 운영자 사이의 대화예요. 서버가 참여 여부·현재 계정 권한·가게 상태를 확인하며 자기 가게에 새 문의를 만들 수 없어요.

- 최근 메시지부터 커서로 나눠 읽어요.
- 전송 식별자로 중복 메시지를 구분하고 읽지 않은 수를 함께 갱신해요.
- 연결 복구·화면 복귀 때 서버 기록과 다시 맞춰요.
- 전송 실패 시 작성 중인 내용과 선택 사진을 유지해요.
- PC는 패널, 모바일은 전체 화면을 사용하며 뒤로가기·닫힘 모션·포커스·모션 줄이기 설정을 보존해요.

## 대화 설정과 관리

고객지원의 이름·원형 사진·인사말·자주 묻는 질문은 미리보기 후 저장해요. 가게 문의의 이름과 사진은 가게 정보를 사용해요. 사진 등록·확대·삭제·기본 사진 복귀는 공통 컴포넌트를 재사용해요.

| 기능 | 처리 기준 |
|---|---|
| 내 목록에서 숨기기 | 내 목록에만 적용해요 |
| 전송 취소 | 허용된 조건에서 내가 보낸 내용을 취소해요 |
| 차단 | 상대와의 전송을 제한해요 |
| 신고 | 원문과 증거를 관리자에게 전달해요 |

일반 메시지와 사진은 전송일부터 90일 보관해요. 기존 자료의 기간 정리는 고지·유예기간을 확인해 시작하고, 처리 중인 신고·분쟁·보존 요청의 증거는 별도로 유지해요. 신고 증거 조회는 관리자 권한과 접근 기록을 요구해요.

## 사진 저장과 조회

서버가 사진의 실제 형식·크기를 확인하고 AES-256-GCM으로 암호화해 저장해요. 조회마다 참여 권한·숨김·전송 취소 상태를 확인한 뒤 복호화하며 공개 CDN으로 제공하지 않아요. HTTP 응답은 no-store를 사용해요.

| 위치 | 재사용 범위 |
|---|---|
| 브라우저 | 참가자가 본 사진의 Blob, 최대 16MiB·24개·2분 |
| 서버 | 권한 검사 후 읽은 암호문, 최대 16MiB·128개·2분 |

- 보이는 영역 주변만 동시 두 개씩 읽고 같은 세션·대화의 동일 사진 요청을 합쳐요.
- 브라우저 캐시를 재사용할 때 HEAD로 현재 권한과 사진 상태를 다시 확인해요.
- 로그아웃·계정 전환에서는 전체 캐시를, 회수·개인 삭제에서는 해당 사진을 비워요.
- 신고 증거는 브라우저 캐시·요청 병합에서 제외하고 조회마다 접근 기록을 남겨요.
- 파일 삭제 시 서버 캐시도 무효화해요. 사진 원본은 보존 조건을 확인한 저장 작업으로 삭제해요.

## 암호화 키와 지표

CHAT_IMAGE_ENCRYPTION_KEY는 32바이트 난수를 표준 Base64로 인코딩한 서버 전용 키예요. 브라우저 환경 변수나 저장소에 넣지 않아요. 키를 잃으면 기존 사진을 복호화할 수 없어요. 기존 사진이 있는 동안 임의로 교체하지 않으며, 암호문과 대응 키를 함께 복구할 수 있도록 보호해요.

reserve.chat.image.cache.reads·reserve.chat.image.cache.bytes는 캐시 사용을, reserve.chat.image.s3.requests·reserve.chat.image.s3.bytes는 S3 SDK 호출과 성공한 암호문 본문 크기를 기록해요. SDK 내부 재시도와 실제 청구액은 별도 확인이 필요해요.

## 코드 위치

화면은 frontend/src/components/chat, 서버는 backend의 chat·file 영역에 있어요.
