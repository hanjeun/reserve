# 공개 화면 디자인 후속 실측

2026-09-13 · `local-preview-all-changes` 로컬 프리뷰. 디자인 수정과 공개 화면 관측 기록이며 운영 배포·업무 기능의 최종 검증이 아니다.

> 아래 30개 실측은 첫 후속 디자인의 스냅샷이다. 이후 사용자 피드백으로 PC 포스터 병렬 배치를 폐기하고 단일 가로 배너로 수정했다. 최신 배너 수치는 문서 마지막의 ‘PC 배너 재수정’에 별도로 기록하며, 첫 실측의 배너 수치를 현재 상태의 증거로 재사용하지 않는다.

## 첫 실측 시점의 결정과 수정

사용자 최종 답변에 따라 서비스 분야와 별점/정렬은 **PC·모바일 모두 오른쪽에 나란히** 둔다. 이전 왼쪽 정렬 요청을 현재 정책으로 재사용하지 않는다.

| 항목 | 수정 전 관측/코드 | 첫 실측 시점 배치 |
|---|---|---|
| 분야·정렬 | 왼쪽에 두 메뉴 | 오른쪽 끝, 사이 4px; 가게 수는 왼쪽 |
| 정렬 팝업 | 최소 144px 폭, 6px 여백, 16px 반경, 44px 행 | 128px 폭, 4px 여백, 10px 반경; 모바일 40px·PC 36px 행 |
| PC 워드마크 | 30px·900 굵기·-1.4px 자간, 상위 글꼴 상속 | 원래 Header의 Pretendard·22px·850·-0.8px 복원 |
| PC 뒤로가기 | 하위 화면에서 로고 옆 표시 | 숨김; 모바일 기존 뒤로가기 유지 |
| 탐색 탭 | 모바일 46px·PC 52px | 모두 44px; 헤더는 그대로 64px |
| 사진 배너 | 모바일/태블릿/PC 비율이 달라 긴 PC 크롭 | 당시 모두 원본 3:2; 포스터 병렬 배치는 후속 수정으로 폐기 |
| PC 검색 화면 | 검색 필드 약 1148px 폭 | 헤더 검색과 같은 최대 560px, 자체 행은 64px |
| 상세 문의 | 평점 아래 큰 독립 버튼, 약 124×44px | 가게명 옆의 `문의`, 56×44px, 13px 글자 |
| 상세 제목·소개 | 28px 제목, 소개를 좁은 정보 표에 표시 | 모바일 22px·PC 24px; 이름 → 평점/리뷰 → 소개 |
| 모바일 상세 여백 | 바깥 여백에 내부 16px가 또 더해짐 | 20px로 정리, 359px 이하는 16px |
| Hover | 일부 객체 투명도만 변화 | 홈 바로가기 이미지·추천 행·공개 탐색 hoverable 카드만 2px 상승 |

문의는 PC·모바일 공용 `StoreIdentity`에 배치한다. 가게 소유자 제외 조건, 기존 로그인 경계와 메신저 진입 동작은 바꾸지 않았다. 소개 행을 정보 표에서 중복하지 않으며 예약 마감·단위·인원·환불·결제 정보는 기존 행 빌더를 유지한다.

원래 StoreCard의 각진 모서리·그리드·사진 원본 비율, 홈 추천의 작은 좌측 썸네일/우측 설명 행, 기존 컷아웃 자산은 보존했다. 큰 목록 제목·설명과 중복 본문 검색은 이미 제거된 상태를 유지했다. 법적 고지 푸터는 고정 하단 페이지 메뉴와 구분하여 유지한다.

## 참고 사이트에서 실제 확인한 범위

사이트의 현재 공개 화면을 브라우저로 열어 DOM, 접근성 트리, 주요 요소의 `getBoundingClientRect()`와 계산된 CSS, 읽을 수 있는 스타일 규칙을 비교했다. 타사 로고·사진·CSS 파일을 복사하지 않았고 로그인 뒤 화면이나 모든 하위 페이지를 수집하지 않았다. 일부 교차 출처 스타일시트의 원문은 접근할 수 없으므로 전체 CSS를 읽었다고 주장하지 않는다.

### KREAM

- [공개 홈](https://kream.co.kr/): 1440px 레이아웃에서 상단 전체 약 130px = 유틸리티 22px + 주행 64px + 탐색 탭 44px. 주행 안의 검색/장바구니 동작 영역은 40×40px였다.
- 홈 배너는 원본 2400×960, 표시 약 1188×475px로 전용 2.5:1 가로 자산이었다. 이 점이 RESERVE의 모바일 3:2 사진을 무조건 넓게 잘라 쓰지 않은 이유다.
- [SHOP 목록](https://kream.co.kr/search): 카테고리 탐색·바로가기 레일·배송/분류/성별/색상/브랜드/크기/가격 필터와 개수/정렬, 상품 그리드를 DOM에서 확인했다. 이 페이지의 모든 그리드 치수를 실측한 것은 아니다.
- [관측한 상품 상세](https://kream.co.kr/products/12831): 공통 헤더를 유지한 좌측 사진/우측 이름·가격·액션 구조. 1440px에서 주사진은 약 680×680px, 판매 액션은 약 56×52px, 구매 액션은 약 294×52px였다. 구매/판매는 누르지 않았다.
- 공개 스타일의 다음 화살표는 사진 위에 절대 배치하고 세로 중앙 정렬하는 구조였다. 상품 사이트의 가격/거래 기능을 RESERVE에 이식하지 않았다.

### 캐치테이블

- [공개 홈](https://app.catchtable.co.kr/): 390px 레이아웃에서 상단 행 48px, 탭 44px·글자 14px. 배너는 원본 750×492, 표시 약 348×229px였다. 카테고리는 5열 물체 이미지 구조다.
- [공개 가격대 목록](https://app.catchtable.co.kr/ct/exhibition/200622_price_level_5to10?isUseExhibitionFilter=1&metaContractedType=0&currentExhibitionKey=200622_price_level_5to10&serviceType=DINING&sortMethod=review_count&isInitialDate=0&uniqueListId=1789298911823): 제목 20px, 뒤로가기/공유 32px, 필터 pill 36px·글자 14px·반경 40px·가로 여백 12px. 이름/평점 위계, 사진 레일, 개수와 정렬 분리를 확인했다.
- 목록의 실제 정렬 팝업을 열었다. 약 125×266px·여백 10px 8px·반경 8px, 6개 항목은 약 109×41px·글자 14px였다. 이를 기준으로 RESERVE의 4개 정렬 항목을 더 조밀하게 정리했다.
- [관측한 가게 상세](https://app.catchtable.co.kr/ct/shop/vinolic?type=DINING): 첫 사진 약 320×240px·반경 16px, 이름 24px, 이름 옆 비교 액션 약 62×36px. RESERVE도 문의를 이름 옆 보조 액션으로 묶되 클릭 영역 44px는 유지했다.
- 공개 헤더 CSS는 유동적인 중앙 프레임/양끝 정렬·10px 16px 여백과 말줄임하는 제목 구조였다. 캐치테이블의 최대 폭 480px를 RESERVE PC 제한으로 복제하지 않았다.

## 로컬 반응형 실측

비로그인 브라우저의 CSS 레이아웃 폭을 바꿔 측정했다. 실제 iOS Safari·기기 터치 환경 시험은 아니다. 화면 폭은 320 / 390 / 768 / 900 / 1440 / 1920px이다. 소수점은 브라우저 배율/반올림 영향을 포함하므로 아래는 근사치다.

홈·전체 가게 목록·가게 상세 `/store/12`·검색을 각 6개 폭에서 측정했다. 혜택·웨이팅·피드는 각 390/1440px 두 폭에서 측정하여 총 30개의 유효 레이아웃 기록을 확인했다. 초기 로딩 중의 빈 측정은 버리고 실제 콘텐츠가 나온 뒤 측정했다.

| 폭 | 홈 포스터 한 장 | 목록 열 | 분야·정렬 오른쪽 끝 차이 | 상세 제목 | PC 뒤로가기 | 전용 검색 폭 |
|---|---|---|---|---|---|---|
| 320 | 288×192 | 1 | 0px | 22px | 해당 없음, 모바일 표시 | 236px |
| 390 | 350×234 | 1 | 0px | 22px | 해당 없음, 모바일 표시 | 298px |
| 768 | 344×230 | 2 | 0px | 22px | 해당 없음, 태블릿 표시 | 668px |
| 900 | 410×274 | 3 | 0px | 24px | 숨김 | 560px |
| 1440 | 540×360 | 4 | 0px | 24px | 숨김 | 560px |
| 1920 | 540×360 | 4 | 0px | 24px | 숨김 | 560px |

- 30개 기록 모두 문서 가로 overflow 0px, 로드 완료 후 깨진 이미지 0개였다. 모든 업무 화면을 검증했다는 뜻은 아니다.
- 공통 헤더 64px, 헤더 검색 pill 44px, 주요 화면 탭 44px. 가게 상세와 전용 검색에는 주요 탭이 없다.
- 목록 사진은 실제 원본 1200×630 / 512×512 비율을 그대로 유지했다. 1440/1920px에서 각각 약 268×141 / 268×268px였다.
- 홈 추천은 900px 미만 1열, 이상 2열의 동일한 썸네일 행이다.
- 실제 정렬 메뉴는 PC 128×152px(36px 행 4개), 모바일 128×168px(40px 행 4개)였다. 입력칸이 아니라 `LI` 메뉴 항목이 포커스를 받아 선택 메뉴 자체가 검색 키보드를 요구하지 않는다.
- 비로그인 프로필 메뉴는 PC·모바일 모두 약 130×209px, 현재 화면 안에 들어왔다. 로그인 후 긴 이름·관리자/사업자 항목은 이 실행의 실측 대상이 아니다.
- 전용 검색은 높이 44px·반경 100px이며 별도 제출 버튼은 0개다. 입력 포커스는 중립 테두리다.

## 상태와 캐러셀 관측

- 개발자 스타일 검사로 hover를 강제한 뒤 계산된 스타일을 확인했다. 홈 물체와 추천 행, 공개 목록 hoverable 카드는 `translateY(-2px)`이고 헤더 검색창은 이동하지 않는다.
- 목록 카드 전환은 그림자 0.2초/이동 0.16초, 원래 사진 줌은 1.05다. 모션 감소를 켜자 카드 이동·사진 줌·전환이 모두 꺼졌다. 검사 뒤 강제 hover와 임시 미디어 설정을 해제했다.
- 실제 Tab 키로 홈 탭·헤더 검색 링크를 이동하여 `:focus-visible`과 중립 보조색 링을 확인했다. 기본 업무 컴포넌트의 primary 포커스·선택 날짜·오류 상태를 전역 제거하지 않았다.
- 여러 포스터가 보이는 PC 캐러셀의 다음 버튼은 마지막 스크롤 위치에서 처음으로 돌아온다. 모션 감소 상태에서 실제 두 번 클릭하여 끝 위치 약 452px → 0px 복귀를 확인하고 설정을 복구했다. 자동 재생은 없다.
- 화면 폭 강제 시 캡처 합성/배율 때문에 스크린샷에 일부 잘림·반복 영역이 나타날 수 있었다. 이를 실제 DOM 중복이라고 판단하지 않고 노드 수와 계산된 박스로 구분했다. 레이아웃 수치는 정상 로드된 DOM에서 얻었다.

## 검증 범위와 남은 확인

최종 관련 JSX 두 파일의 ESLint, 변경 CSS 두 파일의 PostCSS 파싱/한글 선택자 삼킴 검사, 해당 Git 추적 변경의 `git diff --check`가 모두 통과했다. 전체 빌드·Vitest·백엔드·전체 E2E는 디자인 집중 요청에 따라 돌리지 않았다.

인증된 메신저·관리자·사업자·실제 예약/결제/즐겨찾기 변경, 실기기 Safari, 운영 화면은 아직 이 기록으로 증명할 수 없다. 문의의 외형/배치는 확인했지만 메시지를 보내지 않았다. 공개 참고 사이트에서는 예약·공유·관심·구매 등 외부 변경을 실행하지 않았다.

수정은 프론트 디자인과 관련 문서에 한정한다. 기존 미커밋 변경을 보존하며 Git·GitHub·AWS·서버·DB를 변경하지 않았다.

## PC 배너 재수정

사용자의 ‘계속 수정’ 요청에 따라 PC 포스터 병렬 배치를 단일 2.5:1 가로 배너로 교체했다. 전용 1600×640 사진 3장을 생성했고 모바일 960×640 사진은 그대로 둔다. 자산과 최종 프롬프트는 [home-visual-assets.md](../../home-visual-assets.md)에 기록했다.

동일한 로컬 홈에서 브라우저 viewport 기능과 실제 DOM 박스로 아래 크기를 확인했다. 브라우저 세로 스크롤바가 차지하는 폭을 포함하므로 모바일/태블릿 치수는 실기기 Safari의 치수와 다를 수 있다.

| 설정한 화면 폭 | 현재 한 장의 표시 크기 | 실제 선택 자산 | 문서 가로 overflow |
|---|---|---|---|
| 390px | 약 335×223px | 기존 960×640 모바일 사진 | 없음 |
| 768px | 약 705×470px | 기존 960×640 모바일 사진 | 없음 |
| 1440px | 1200×480px | PC 전용 1600×640 사진 | 없음 |
| 1920px | 1200×480px | PC 전용 1600×640 사진 | 없음 |

PC에서 보이는 사진의 교차 폭은 매번 한 장 1200px / 나머지 두 장 0px였다. 모션 감소 설정에서 실제 다음 버튼으로 `1 → 2 → 3 → 1`을 확인했다. 스크롤 위치는 `0 → 1216 → 2432 → 0px`, 표시 번호는 보이는 사진과 일치했다. 두 번째 사진에서 PC → 모바일 → 태블릿 → PC로 폭을 바꾸어도 사진 선택과 `2 / 3` 표시가 유지됐다. 페이지 표시 버튼은 현재 사진 프레임 안에 있었다.

PC와 모바일의 실제 화면 캡처로 사진·제목 배치를 확인했다. 일시적인 캡처 합성 이상은 화면을 갱신한 후 다시 관측했다. 이번 후속 검증은 홈 배너에 한정하며 기존 30개 경로 측정이나 업무 기능을 재검증했다고 주장하지 않는다. `Home/index.jsx` ESLint, `feature-surfaces.css` PostCSS 파싱/한글 선택자 검사, `git diff --check`는 통과했다. Git 검사는 기존 일부 파일의 CRLF 정규화 경고만 남겼다. 전체 테스트·빌드·배포는 실행하지 않았다.
