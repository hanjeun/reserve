# 디자인 시스템

공통 토큰과 컴포넌트를 사용해 화면의 색·크기·상호작용을 유지해요.

## 토큰과 스타일

| 위치 | 역할 |
|---|---|
| frontend/src/styles/tokens | 색·글자·간격·모서리·모션 값 |
| frontend/src/styles/theme.css | 테마 CSS 변수 |
| frontend/src/styles/global | 공통 상태와 화면별 CSS |
| frontend/src/index.css | 전역 CSS 진입점 |

컴포넌트의 지역 배치는 인라인 스타일로, hover·focus·반응형 규칙은 기존 전역 CSS에서 관리해요.

## 모양

- 작은 텍스트 실행 버튼은 pill 모양을 사용해요.
- 빠른 검색 칩, 한 줄의 분류·보기 칩, 패널 안의 선택 탭은 같은 44px 최소 높이·14px 글자·22px 줄 높이·좌우 15px 여백과 둥근 테두리·테마의 종이색 바탕을 써요. 선택한 항목은 본문 글자색 테두리와 굵은 글자로 표시해요. 여러 줄 폼 선택지는 줄바꿈과 기존 여백을 유지해요.
- 빠른 검색·한 줄 분류·패널 선택 탭의 둥근 칩은 항목 사이를 8px로 맞춰요. AntD Tabs에는 tabBarGutter로 전달해 넘침 계산에도 같은 간격을 적용해요. 여러 줄 폼 선택지는 기존 간격을 유지해요.
- 일반 버튼·입력·선택·카드는 각 역할의 기존 모서리를 유지해요.
- 프로필 사진과 사진 선택기는 원형이에요.
- 같은 역할의 컴포넌트를 재사용하고 서로 다른 컨트롤을 한 모양으로 바꾸지 않아요.
- 가게 소식과 혜택 심사는 공통 가게 카드·목록의 사진, 제목, 간격, 눌림과 골격을 사용해요. 본문을 누르면 미리보기나 검토가 열려요. 데스크톱 관리 메뉴가 열려 있으면 예약·가게 소식·혜택 카드와 골격의 열을 본문 폭에 맞춰 정해요. 목록의 오른쪽에는 상태를 위에, 작업 도구를 아래에 두고 예약 목록과 버튼 간격을 공유해요.
- 좋아요 카드의 보기·가게·하트·신고는 사진 아래의 독립된 작업 줄에 두고 제목과 본문을 그 아래에 표시해요. 가게 링크가 없어도 도구의 열 위치를 유지해요.

## 아이콘 도구

| 역할 | hover 면 |
|---|---|
| 검색·뒤로·현재 위치·사진 위 하트 | 원형 |
| 닫기·새로고침·작성·보기 전환·읽음 도구 | 둥근 네모 |

공통 기준은 클릭 영역 44px, 보이는 면 32px, 아이콘 20px예요.

명확한 검색·뒤로·닫기·보기 전환에는 툴팁을 생략하고 접근성 이름을 유지해요. 설명이 필요한 도구는 공통 Tooltip을 사용해요. 모달의 닫기는 제목의 첫 줄 오른쪽에 두고 긴 제목은 닫기 영역 앞에서 줄바꿈해요. 로그인 및 보안의 추가 패널은 열리면 더하기가 회전해 X가 돼요. 패널 안의 닫기는 제목 오른쪽에 두고, 등록된 기기나 개별 인증 수단의 해제는 해당 항목 옆에 빼기 아이콘으로 표시해요.

PC에서는 hover·키보드 포커스, 터치에서는 500ms 길게 누르기로 짧은 설명을 표시해요. 손을 떼거나 스크롤하면 닫고 길게 누른 동작의 클릭은 실행하지 않아요. 링크의 기본 길게 누르기와 InfoHint의 설명 고정은 구분해요.

## 텍스트 링크와 동작

푸터와 같은 중립 텍스트는 기본 보조색에서 hover·키보드 포커스·누름 상태에 진한 글자와 밑줄을 표시해요. 비활성 상태에는 이 효과를 적용하지 않아요.

이동은 TextLink, 간단한 실행은 UnderlinedTextButton을 재사용해요. Button의 중립 ghost·ghost-sm과 검색 취소·최근 검색 전체 삭제도 같은 text-links.css 규칙을 사용해요. 강조색 버튼·아이콘 도구·채움 버튼·선택 칩은 각 역할의 기존 상태와 모양을 유지해요. 기기 등록이나 복구코드 보관 완료처럼 진행하는 동작에는 문구를 표시해요. 기기 관리 인증 수단은 같은 줄에 배치하고 좁은 화면에서는 줄바꿈해요. 소셜 로고와 패스키·인증 앱 코드·복구코드의 공통 아이콘을 쓰고 툴팁과 접근성 이름으로 구분해요. 선택한 인증을 취소하거나 마치지 못하면 같은 항목의 수단 선택으로 돌아와요.

추가 인증에서 코드를 입력할 때는 이전·확인을 한 줄에 둬요. 인증 앱 등록 단계에서는 이전·등록을 같은 배치로 사용해요.

## 입력과 선택

| 컴포넌트 | 용도 |
|---|---|
| FormInput·FormTextArea | 일반 텍스트 입력 |
| FormSelect | 폼 안의 값 선택 |
| FilterMenu | 목록의 분야·정렬 선택 |
| SegmentedControl·SegmentedGrid | 화면에 펼쳐 둔 분류·보기 선택 |
| FormDatePicker·FormTimePicker | 날짜·시간 입력 |
| FormField·Form.Item | 입력 이름과 검증 오류 |

선택 그룹은 이름을 제공하고 선택된 항목 한 곳에서 Tab으로 진입해요. 방향키·Home·End로 이동하며 비활성 항목은 건너뛰어요.

검증 오류는 해당 입력 아래에 표시하고, 값이 올바르게 바뀔 때 해제해요. 정상 0건과 조회 실패는 다른 화면으로 표현해요.

목록·통합·채팅 검색과 이모지 검색 입력은 테마의 종이색 배경을 사용해요. 라이트에서는 흰색, 다크에서는 해당 테마 배경을 따르며 포커스·비활성 상태를 구분해요.

가게 상세와 결제 요약의 아이콘·보조색 라벨·값·구분선은 DetailInfoRows를 재사용해요. 예약·광고의 결제 확인과 광고 신청 미리보기는 PaymentCheckoutSummary로 상세 목록과 총액을 보여줘요. 결제 브랜드 표시는 원본 비율과 고유 색을 유지하고 단색 로고는 테마에 맞는 밝기로 표시해요.

관리자 영수증 조회는 결제 운영의 안내 영역과 공통 폼 입력·전체 폭 제출 버튼을 사용해요. 영수증과 고객 확인 링크는 DetailInfoRows로 정렬해요.

## 사진과 상태

- 프로필 사진은 ProfilePhotoPicker를 사용해요. 마이페이지의 프로필에서 공개 닉네임·소개·사진·공개 범위를 함께 편집해요.
- 기본 사람 프로필은 공통 선 아이콘과 투명 배경을 사용하며 사진의 원형 틀을 유지해요.
- 고객지원 사진은 ProfilePhotoUpload로 원형 등록·확대·삭제를 제공해요.
- 기본 사진 복귀는 ProfilePhotoResetButton을 사용해요.
- 일반 사진 등록은 LoadingUpload·ImageUploadButton을 재사용해요.
- 여러 장의 사진 등록 칸은 왼쪽에 고정하고 선택한 사진은 오른쪽으로 이어지는 한 줄에 배치해요. 넘치는 사진은 가로로 스크롤하고, 미리보기·삭제 도구는 44px 클릭 영역과 12px 간격·구분선으로 나눠요.
- 리뷰 사진 모아보기는 PC 본문 폭에 맞춰 첫 줄을 채워요. 다음 줄이 있는 경우에만 사진 더 보기로 펼치고, 사진이 적으면 남는 가로 폭을 나눠 사용해요.
- 가게 리뷰는 최근 10개부터 표시하고 리뷰 더 보기에서 다음 목록을 요청해요. 사진 모아보기에는 최대 10장의 작은 사진을 원본 비율로 표시해요. 크게 보기에서는 현재 사진이 준비되는 동안 스피너를 표시해요.
- 빈 상태와 조회 오류는 DataState·PageStatus와 기존 StateIllustration 3D 그림을 사용해요. 같은 상태는 안내 크기와 관계없이 같은 그림을 써요. 서버 연결·오프라인 상태는 그림 요청이 실패하면 스타일에 포함된 작은 3D 그림을 사용해요. 나머지 상태는 이미지 로딩에 실패하면 선 아이콘으로 대체해요.
- 로딩 골격은 실제 본문의 크기와 배치에 맞춰요.

DataState의 단독 안내는 그림·본문·동작을 가운데 배치해요. 기존 내용을 유지하는 compact 안내는 sm 그림 옆의 한 본문 영역에 제목·설명·동작을 순서대로 두어요. 제목은 진한 글자, 설명은 보조색을 사용하며 긴 문구와 동작은 영역 안에서 줄바꿈해요. 화면별로 작은 아이콘용 열 너비나 재시도 버튼 위치를 덮어쓰지 않아요.

즉시 적용하는 마이페이지 스위치는 켜거나 끈 결과를 상단 알림으로 보여줘요. 서버에 저장하는 설정은 저장이 끝난 뒤 값을 바꾸고, 실패하면 기존 값과 오류 안내를 보여줘요. 같은 설정을 연달아 바꾸면 최신 안내로 교체해요. 작성 폼의 스위치는 입력값을 바꾸고 저장할 때 다른 입력값과 함께 처리해요.

예약 날짜·시간과 요청 사항의 입력 전 안내는 같은 보조색과 글자 규격을 사용해요. 날짜·시간·인원 수·요청 사항의 글자 시작선을 맞추고, 선택된 날짜와 인원 수는 중간 굵기로 표시해요. 값 전환의 원근 효과는 애니메이션 중에만 적용하고 정지한 글자는 일반 레이어로 표시해요.

예약 시간은 분류 선택 칩과 같은 둥근 테두리·배경·44px 최소 높이를 사용해요. 선택된 시간은 진한 테두리와 굵은 글자로 표시하고 항목 사이에는 8px 간격을 둬요. 진입·퇴장과 누름 효과는 서로 덮어쓰지 않으며 로딩 골격도 같은 높이와 모서리를 사용해요.

예약 인원은 가게 정원과 선택한 시간의 잔여석에 맞춰 제한해요. 시간 조회의 `remainingCapacity`가 `null`이면 슬롯 정원 제한이 없어요. 예약 변경 조회는 소유권을 확인한 뒤 변경할 예약의 인원을 계산에서 제외해요. 갱신 중에는 기존 시간 버튼을 유지하고, 마감된 시간은 즉시 선택을 막은 뒤 짧은 퇴장 모션으로 제거해요. 모션 줄이기에서는 바로 제거해요. 가능한 시간이 없는 날짜는 달력에서 비활성화해요.

## 모션

가게 상세·확대 사진은 500ms ease 전환을 사용해요. 피드·댓글·리뷰의 가로 사진은 마우스를 놓은 위치와 속도에 따라 가까운 사진에 정착하고, 터치는 브라우저의 기본 스크롤을 사용해요. 새 조작·휠·화면 이탈에서는 진행 중인 전환을 정리하고, 모션 줄이기에서는 바로 이동해요.

페이지는 처음 보이는 본문이나 페이지 골격에서 한 번만 진입해요. 골격이 본문으로 바뀔 때 다시 실행하지 않아요. 지도·달력 같은 부분 로딩은 페이지 진입과 구분해요. 좁은 화면의 탐색 본문은 가로 드래그를 따라가며, 충분히 밀거나 빠르게 튕기면 옆 탭으로 이동해요. 배너·입력·가장자리 제스처는 각 영역에서 처리해요.

홈의 지역별 BEST는 밑줄형 지역 탭과 공통 가게 목록 행을 사용해요. 지역 탭의 선택선은 서비스 탐색과 같은 2px이며 글자 크기·색·선택 굵기도 맞춰요. 모바일에서 목록을 가로로 밀면 옆 지역으로 이동하고, 세로 스크롤과 확대는 브라우저에서 처리해요. 지역을 고르면 목록이 짧게 전환돼요. 조회한 지역은 캐시를 사용하고, 처음 보는 지역은 목록 자리에 골격을 보여줘요.

모바일 가게 상세는 헤더 아래에 소개·위치·예약·리뷰 섹션 이동을 고정해요. 주소는 소개에 표시하고 위치 탭은 지도에 연결해요. 실제 제공하는 섹션에 연결하고 웨이팅만 받는 가게에는 웨이팅을 표시해요. 스크롤이 지도에 도달하면 서비스 탐색과 같은 2px 밑줄을 위치로 옮기며 모션 줄이기에서는 바로 이동해요.

빠른 세로 스크롤은 브라우저의 관성 동작을 사용해요. 상단 알림은 손이나 마우스로 위로 밀어 닫을 수 있어요. 아래로 당겼다가 놓으면 제자리로 돌아오고, 잡은 동안에도 표시 시간이 끝나면 위로 닫혀요.

검색과 메신저는 각 화면의 열림·닫힘 동작을 사용해요. 검색도 처음 보인 골격 또는 본문에서 한 번만 진입해요. 닫히는 요소는 모션이 끝날 때까지 유지하고 중복 조작을 막아요.

통합검색의 가게 결과는 둥근 사각형에 공개 대표 사진을 표시해요. 사진을 표시할 수 없으면 같은 자리에 가게 아이콘을 사용해요.

정보 수정 탭, 관리 메뉴, 카드·목록, 내 예약·웨이팅의 전환은 선택한 본문에만 적용해요. 공통 표는 페이지·정렬·필터를 바꿀 때 결과를 전환하고, 통계의 데이터 표는 접근성 상태와 함께 펼치고 접어요. 동일한 보기의 재조회나 골격에서 본문으로 바뀌는 동작은 다시 재생하지 않아요.

롤러는 바뀐 선택값을 짧게 전환해요. 같은 범위에서 정렬만 바꾸면 현재 결과와 페이지를 유지하고 정렬 도구에 진행 상태를 표시해요. 다음 결과의 순서나 항목이 달라지면 본문만 짧게 전환해요. 첫 조회나 캐시가 없는 새 검색 조건에는 목록과 같은 골격을 쓰고, 응답이 오면 바로 본문을 표시해요.

PC에서 채팅 본문을 마우스로 누르면 기존 관리 메뉴를 열어요. 글자 선택과 사진 확대는 그대로 사용하며, 터치의 길게 누르기와 키보드의 관리 버튼도 유지해요. 나에게만 삭제가 완료되면 본문과 사진은 제거하고 빈 행의 높이만 접어요.

모션 줄이기 설정에서는 이동·확대 효과를 줄이거나 생략해요. 선택 상태와 키보드 포커스는 유지해요. 결제 남은 시간은 고정 문구·콜론을 유지하고 바뀌는 숫자 자리만 기존 RollingFieldValue로 전환해요. 1분 이하·만료의 색상은 전환하고 만료 문구는 공통 AnimatedContent를 사용해요.

앱 홈과 소개 본문은 한국 시간 3월 20일~4월 30일에 꽃잎, 7월 15일~8월 15일에 빛점, 10월 15일~11월 25일에 낙엽, 12월 15일~1월 25일에 눈을 지연 로드해요. 기간의 시작일과 종료일을 포함해요. 소개에서는 헤더 아래 첫 장면부터 시연과 FAQ 뒤까지 이어지며 푸터 시작에서 끝나요. 배경 장식은 클릭을 가로채지 않고 화면 밖·비활성 탭·모션 줄이기 상태에서 정지해요. 앱 홈의 계절 효과는 마이페이지의 디자인에서 조절해요. 브라우저에 저장한 선택을 이후 계절에도 적용해요. 소개 본문은 기간에 맞춰 자동으로 적용해요.

소개 사이트의 기기는 Figma의 iPhone 16 Pro 프레임과 상태 표시줄 원본을 사용해요. 450×920 외형 안에 402×874 화면을 왼쪽24·위23 기준으로 배치하고 프레임·SVG의 원래 비율을 유지해요. 서비스 시연은 별도 iframe에서 실제 가게 목록·상세·내 예약·웨이팅·QR 컴포넌트와 index.css를 사용해요. AntD 테마·입력 검증·메시지는 실제 앱과 appProviderConfig를 공유하고 밝은 테마·프리텐다드로 고정해요. 각 장면의 경로를 고정하고 같은 화면의 예약·웨이팅 탭 전환, 검색·필터·입력·즐겨찾기·예시 예약과 취소는 메모리에서 처리해요. 홈·프로필·뒤로 등 다른 페이지 이동은 제공하지 않아요. 예약 입장 창은 대기 대상이거나 입장 확인에 실패했을 때 열어요. 대기 없는 예약 시연의 성공은 공통 성공 메시지로 표시해요. 예시 가게의 운영 시간·휴무·예약 범위·마감·정원·중복·필수 동의는 날짜와 시간 조회 및 예약 요청에 적용해요. 시연을 열면 다음 영업일의 15시만 두 자리가 남아 있어요. 실제 계정·예약 API나 저장소를 사용하지 않고 QR에는 공개 예시 주소만 넣어요. iframe은 same-origin 권한 없이 실행하며 저장소 격리 스크립트를 화면 코드보다 먼저 불러와요. 화면에 보일 때 처음 로드해요. 시연이 처음 그려질 때까지 기기 화면에 골격을 표시해요. 화면 밖·비활성 탭에서는 갱신과 CSS 애니메이션을 쉬어요. 소개 시연 문서 안의 스크롤 막대만 숨기고 휠·터치·키보드 스크롤과 입력·모달의 스크롤 영역을 유지해요. 기기 안의 긴 본문은 내부에서 스크롤하고 작은 화면에서는 기기 전체의 별도 정지 지점을 사용해요. 터치 관성과 CSS 스냅에 별도 터치 종료 이동을 겹치지 않고 모션 줄이기를 보존해요.

소개 페이지 헤더 오른쪽에는 로그인·회원가입 아이콘을 배치해요. 첫 화면 중앙의 오른쪽 화살표는 가게 탐색으로 이어져요. 포인터를 올린 동안 화살표가 오른쪽 경계 밖으로 지나가고 왼쪽 경계에서 다시 들어와요. 키보드 초점에서는 같은 움직임을 한 번 보여줘요. 설명이 필요한 단계 탐색 도구의 툴팁은 실제 대상의 사각형으로 위치를 계산해 화면 경계를 넘지 않게 하고 스크롤·닫기·포커스 해제 시 지워요. 링크의 터치·길게 누르기는 가로채지 않아요. 모바일은 제목 다음에 기기를 두고 전체 묶음의 위아래 여백을 같게 해요. 타이핑 문구는 전체 문구 높이를 미리 확보해 배치가 흔들리지 않게 해요. 헤더와 푸터는 불투명 paper 바탕을 공유하고 움직이는 그라데이션은 FAQ까지 소개 본문 뒤에 보여요. 넓은 화면의 옆 단계 표시는 44px 버튼으로 해당 장면을 탐색하고 작은 화면에서는 입력을 가리지 않는 비대화형 표시만 사용해요. 배경 당김은 입력·기기 시연·기본 터치 스크롤과 확대를 가로채지 않아요. 비활성 탭/화면 밖에서는 연출을 쉬고 모션 줄이기에서는 이동·확대·영상 탐색을 생략해요.

소개 시연의 스크롤 진행 값은 정해진 상위 창·출처에서만 받고 0~1의 유한한 숫자만 허용해요. 기기 안의 본문 스크롤·실행 도구 강조·예시 호출 상태·QR 표시만 연출하며 계정·동의·예약 제출을 자동 실행하지 않아요. 직접 터치·포인터·휠·키보드 조작을 시작하면 해당 기기의 자동 연출을 멈춰 입력과 모달을 보존해요. 지도는 소개 빌드에서만 외부 SDK 대신 SVG 예시 지도로 교체하고 공통 가게 표식·확대/축소 도구를 사용해요. 메인과 장면 제목은 한글 타이핑을 유지하고 전체 문구의 공간을 미리 확보해요. 숨겨진 단계에서는 타이핑을 진행하지 않고 실제로 열릴 때 시작해요. 본문 제목의 타이핑 대기·입력이 끝날 때까지 추가 전진 휠·키·터치 이동과 다음 단계 실행을 보류해요. 반복되는 메인 문구는 이 잠금에 포함하지 않고 뒤로 이동·확대·입력·기기 내부 스크롤·모션 줄이기를 유지해요. 대기 중 입력은 다음 장면 이동으로 예약하지 않아요. 소개 첫 화면은 가운데 배치한 타이핑 제목과 가게 탐색 화살표로 구성해요. 아래로 이동하면 가게 탐색·간편 예약·예약 관리·웨이팅·QR 체크인 순서로 시연을 열어요.

## 접근성

동작은 네이티브 버튼, 페이지 이동은 링크로 제공해요. 키보드 조작·이름·포커스 표시를 유지하고 버튼 안에 다른 버튼이나 링크를 중첩하지 않아요.

## 화면과 조회 상태

공통 레이아웃을 사용하고 폼·관리·공개 목록의 기존 폭을 유지해요. 목록 조건과 페이지는 주소에 보존하며 조건을 바꾸면 첫 페이지로 이동해요.

광고 관리처럼 열 단위로 읽는 관리 표에는 텍스트·상태·처리 도구를 배치해요. 관리자 혜택 신청 카드·리스트에는 공개 가게 대표 사진을 표시하고 비공개 신청 사진은 검토를 열 때 불러와요.

페이지형 목록 검색은 입력값과 적용값을 구분하고 Enter·검색 아이콘·모바일 검색 키로 확정해요. 한글 조합 중 Enter는 검색하지 않아요. 지우기는 빈 조건과 첫 페이지를 함께 적용하고 Escape는 입력을 적용값으로 되돌려요. 필터·페이지·새로고침·자동 갱신은 적용된 조건을 사용해요. 회원 이름·이메일·예약자·대기자 검색어는 계정별 화면 메모리에만 보관하고 주소·영구 저장소에 넣지 않아요. 조회 범위의 명단을 이미 받은 사업자 웨이팅 검색은 로컬에서 즉시 적용해요.

목록 검색은 FilterToolbar의 ListSearchField를, 수동 갱신은 연결 상태와 무관하게 공통 RefreshButton을 사용해요. 검색창 아래에 별도 안내 영역을 두지 않고 입력과 새로고침을 같은 행에 정렬해요. 첫 골격도 같은 입력 높이와 행 간격을 사용해요.

목록 페이지 이동은 공통 Pagination을 재사용해요. 결과를 다시 불러올 때도 페이지 번호와 포커스를 유지하고, 골격과 전환 모션은 결과 영역에만 적용해요. 전체 건수·페이지 크기는 서버가 계산한 값을 사용하고, 이전·다음 텍스트 버튼이나 추정한 전체 건수로 별도 페이지 이동을 만들지 않아요. 오른쪽에 모으는 간단한 목록 필터는 내용 폭으로 배치하고 골격에도 같은 폭 규칙을 사용해요.

첫 조회와 새 검색에는 본문과 맞는 골격을, 같은 조건의 자동 갱신에는 기존 목록을 유지해요. 정상 0건·일시 오류·접근 거부·삭제를 구분하고 권한을 잃은 자료는 숨겨요.

실시간 조회의 주기는 LiveUpdatesProvider에서 조정해요. 첫 연결은 화면의 최초 조회를 사용해요. 재접속 때 서버가 같은 변경 번호로 유실이 없음을 확인해주면 주기와 실제 이벤트에 맞춰 갱신하고, 누락 가능성이 있으면 활성 목록을 다시 읽어요. 신호가 정상인 가게 목록과 지역 목록은 180초, 다른 실시간 목록은 60초마다 보정해요. 연결이 없으면 승인 대기 내 예약은 10초, 내 웨이팅은 15초, 가게 웨이팅과 대기 명단은 30초에 확인해요. 같은 조회가 진행 중이면 주기 갱신을 겹치지 않고, 실제 변경 신호는 완료 뒤 한 번 더 조회해요. 숨겨진 문서·오프라인·비활성 쿼리는 주기 조회를 쉬어요. 계정별 캐시와 권한 재검증을 유지하고 편집 폼·QR 발급·결제·감사 조회를 주기 갱신 대상으로 확대하지 않아요.

조회 실패는 본문의 DataState에서 안내하고 토스트로 중복 표시하지 않아요. 화면별 제목을 사용해도 확인된 연결 실패·시간 초과·권한·요청 제한·서버 오류의 안전한 설명을 함께 표시해요. 원문 응답이나 내부 오류는 노출하지 않아요. 주 조회와 보조 조회가 함께 실패하면 안내 하나에서 실패한 조회를 함께 재시도하고, 기존 본문을 유지할 수 있으면 작은 안내를 사용해요. 보조 기능만 실패한 경우에는 해당 기능 가까이에 안내해요.

저장 중에는 중복 실행을 막고 실패하면 입력을 보존해요. 실행 결과와 경고는 공통 메시지를 사용해요. 저장 요청의 응답이 끊기면 실패로 단정하지 않고 목록이나 최신 상태를 확인하도록 안내해요. 사진 선택만으로 다른 입력을 저장하지 않아요. 작성·제출 모달은 FormModal과 공통 액션을 사용해요.
