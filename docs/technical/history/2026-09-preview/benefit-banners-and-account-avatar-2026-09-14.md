# 혜택 사진 배너·내 설정 사진 — 2026-09-14 로컬 프리뷰

최신 사용자 참고 사진의 가로 배너 목록을 기준으로 수정했다. 이전 작은 메뉴 카드와 일반 가게 목록을 혜택에 함께 배치한 단계보다 이 기록이 우선한다. 운영 배포 완료 기록은 아니다.

## 변경한 것

- 혜택: 가게 사진 배경 → 짧은 실제 본문 → 큰 가게명 → 실제 소식 제목의 티켓. 작은 메뉴 3개, 중복 제목·설명·건수·날짜·목록 안내 문구를 제거했다.
- 일반 가게 탐색은 `/stores`에서 유지한다. 혜택에서 독립 가게 탐색 컴포넌트를 렌더하지 않으며 해당 소스 자체는 보존했다.
- 실제 공개 소식 GET, 12건 페이지 번호, 중첩/루트 서버 메타, 무관한 URL 값, AbortSignal, 로딩·0건·실패·재시도·백그라운드 갱신을 보존했다.
- 배너는 900px 미만 1열·이상 2열이다. 3.2:1 골격과 최소 높이를 겹치는 grid로 긴 제목의 본문 높이를 수용한다. 사진은 cover이고 전체 배너의 hover/active 축소는 없다. 허용된 실제 사진만 모션 감소가 꺼진 fine pointer에서 확대한다.
- 사진 부재·실패·허용되지 않은 URL은 작은 RESERVE 로고로 표시한다. 사진 URL 변경 시 실패 상태를 초기화한다. 스켈레톤도 일반 배너와 같은 그리드·치수를 사용한다.
- 메시지 설정: `MessengerContent`가 전달하는 현재 로그인 사용자 `profileImageUrl`/`profileImage`를 안전한 URL 검사 후 표시한다. 관리자/운영팀 사진을 내 설정에 사용하지 않는다. 사진이 없거나 실패하면 본인 이름 첫 글자·사용자 아이콘을 표시한다.
- 계정·사진 변경 시 이미지 실패 상태를 초기화한다. 이름·이메일·내 정보 관리와 기존 PC 알림 컨트롤을 보존하고, 실제 컨트롤이 없는 모바일의 환경 구역·구분선·PC 설명·초안 안내를 제거했다.
- 기존 Core는 교체하지 않고 `feature-surfaces.css`의 RESERVE 패턴 토큰과 공통 관문에서 처리했다. 관리자 사진·톡 커버·하단 메뉴의 기존 계약은 유지한다.

## 실제 데이터와 예시의 경계

사진 배너 실측은 DEV 전용 `benefits-and-loading.html?photos=1&long=1`에서 수행했다. 예시 소식 데이터는 실제 혜택이 아니며 사진은 프리뷰 전용 CSS로 기존 로컬 자산을 합성했다. 이 화면을 실제 가게의 혜택·사진 소유권·CDN 네트워크 검증 증거로 쓰지 않는다. 소스의 이미지 URL 검사·실패·교체는 별도 단위 테스트로 확인했다.

설정은 실제 인증 저장소 → `MessengerContent` → `MessengerSettings` 전달 경로를 읽고 확인했지만, 로그인한 실제 두 계정의 프로필 사진 E2E는 실행하지 않았다. 실측 프로필은 명시된 예시 데이터다.

동결 스냅샷 ZIP SHA-256은 기존 기준선과 일치한다: `02d5809dabf319ed1778140210e4303862b5f5a37b0b5ef6dd5d880514af536e`. 스냅샷 내용을 바꾸거나 신규 프로젝트용 실행 패키지를 만들지 않았다.
