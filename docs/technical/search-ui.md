# 검색 화면

상단 돋보기를 누르면 가게·혜택·공개 피드와 본인 내역을 찾는 통합검색을 열어요. 탐색·웨이팅·사업자·관리자 화면의 검색은 해당 목록의 조건이며 상단 돋보기와 연결하지 않아요. 탐색·웨이팅에서 검색해도 상단 서비스 탭과 헤더를 유지해요.

## 입력과 조회

- 빈 입력에는 분야·빠른 검색·기기 최근 검색을 표시해요. 검색어를 모두 지우면 이 기본 화면으로 돌아가요.
- 입력 중 메뉴·별칭·작은 오타 사전은 로컬에서 조회해요. 교정 제안은 원문과 구분하며 선택해야 적용해요.
- Enter나 키보드 검색으로 확정한 입력만 API에 보내요. 조합 중인 한글, 미확정 재입력, 모호한 대상·지역은 원격 조회하지 않아요.
- 날짜는 한국 시간으로 해석해요. 예약 대상·중복 지역은 선택 후 검색해요. 예약 가능 시간과 정원은 상세·신청 단계에서 다시 확인해요.
- 전체 검색과 선택 그룹은 같은 API를 사용해요. 서버는 scope·term·date·region과 길이·결과 상한을 검증하고 선택한 그룹만 조회해요.

## 결과와 권한

- 가게·혜택·공개 피드와 내 예약·웨이팅·메시지를 종류별로 표시해요. 없는 결과의 빈 그룹을 나열하지 않아요.
- 메뉴는 사용자 권한에 맞는 항목만 제시하고, 개인 결과는 서버의 현재 소유권·표시 기간·숨김·차단 정책으로 조회해요.
- 그룹별 최대 5건과 hasMore를 반환해요. 통합검색은 페이지 전체 건수를 계산하지 않아요.
- 한 그룹의 DB 장애는 해당 그룹의 오류로 표시해요. HTTP 200 안의 부분 실패는 그룹·응답 지표로 구분해요.
- 검색으로 예약을 생성하거나 메시지를 읽음 처리하지 않아요. 결과 선택은 해당 상세·대화 경로로 이동해요.

## 캐시와 관측

공개 검색은 기기 메모리에서 30초 재사용하고 그룹·필터를 캐시 키에 포함해요. 개인 결과는 회원·세션별로 분리하고 비관찰 상태나 계정 전환 시 제거해요. 개인 검색은 서버·공유 캐시에 보관하지 않아요.

최근 검색은 사용자가 지울 수 있는 기기 기록이에요. 검색 품질 진단은 검색어·회원 ID·메시지 원문을 보내지 않는 고정 집계값을 사용해요.

## 조작과 모션

입력은 기존 pill·취소 텍스트 동작을 재사용해요. 검색 화면에서는 전역 헤더·푸터를 숨기고 취소·Escape는 진입 전 화면으로 돌아가요.

캐시 본문 또는 첫 골격에서 한 번만 진입하고 골격이 본문으로 바뀔 때 다시 진입하지 않아요. 닫힘 DOM·초점·스크롤·모션 줄이기 설정을 보존해요. PC 메시지 결과는 메신저를 표시할 수 있는 화면으로 인계해요.

구현은 [검색 화면](../../frontend/src/pages/Search/index.jsx), [검색 hook](../../frontend/src/hooks/useUnifiedSearch.js), [검색 서비스](../../backend/src/main/java/kr/it/reserve/search/SearchService.java)를 확인해요.

## 서버 조회와 색인

search 모듈이 결과를 조합하고 개인 조회는 각 도메인의 ReservationSearchReader·WaitingSearchReader·ChatSearchReader가 처리해요. MemberSearchAccess가 현재 회원 상태를 확인해요. 각 그룹은 독립 읽기 트랜잭션·3초 제한으로 최대 여섯 행을 읽어 다음 결과 여부를 판단해요.

가게 FULLTEXT/ngram은 실제 색인·파서·컬럼을 확인하며 앱이 자동 생성하지 않아요. 통합검색의 search.store.unified-fulltext-enabled는 기본 false이며 search.store.fulltext-enabled도 필요해요. 누락 행을 최대 한 건 확인한 뒤 제한 조회하고 누락 시 원문 조건으로 돌아가요. 일반 페이지 API의 전체 건수 계약은 유지해요.

검색 시간·일치·무결과·오류는 reserve.search 지표로 집계하고 부분 실패는 reserve.search.responses로 구분해요. 검색어·회원·결과 ID는 지표에 넣지 않아요.
