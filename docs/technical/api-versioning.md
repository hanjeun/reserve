# API 버전 관리와 릴리스 분리 계획

> 기준일: 2026-09-17. 실제 코드와 배포 상태가 이 문서보다 우선한다.

## 결론

- 제품 JSON API의 새 표준 경로는 `/api/v1/...`로 정한다. `/v1/...`만 쓰면 SPA·정적 파일 경로와 API 경계가 흐려진다.
- **API 버전 `v1`과 애플리케이션 릴리스 `v2.6.0`은 별개다.** API 버전은 외부 계약 세대이고, 앱 버전은 배포 묶음이다.
- 기존 `/api/...`는 `/api/v1/...` 도입과 동시에 제거하지 않는다. 한 릴리스 이상 두 경로를 같은 컨트롤러에 연결하고 프론트를 먼저 옮긴다.
- URL만 바뀌고 응답 계약이 같은 동안에는 컨트롤러·서비스를 복제하지 않는다.

현재 `frontend/package.json`과 `backend/build.gradle`은 모두 `2.5.0`이다. 운영은 v2.5.1이고 로컬
v2.6 변경은 아직 `dev` 병합·production 배포 전이다. 기능별 근거는 [현재 상태](current-status.md)를
따르며, 버전 파일은 실제 릴리스 후보를 고정할 때 CHANGELOG와 함께 올린다.

## 현재 범위

2026-09-17 정적 조사 기준으로 `/api/` 문자열을 가진 파일은 프론트 `src` 53개, 백엔드 `main` 29개다. 결제 웹훅, 인증 갱신, 보안 매처, CSP 수집처럼 단순 문자열 치환으로 끝나지 않는 경로도 포함된다. 일부만 먼저 바꾸면 로그인·결제·공개 조회의 동작이 환경별로 갈라질 수 있다.

Spring Boot 3.5.6의 Spring Framework 6 계열에는 Spring Framework 7의 네이티브 API 버전 기능이 없다. 경로 버전을 위해 Boot 4로 먼저 올리지는 않는다. 현재 스택에서는 다음 방식이 명확하다.

1. `ApiPaths`에 `LEGACY_PREFIX = "/api"`, `V1_PREFIX = "/api/v1"`를 둔다.
2. 각 제품 컨트롤러의 클래스 매핑에 구 경로와 v1 경로를 함께 선언한다.
3. Spring Security 공개·인증·관리자 매처에 두 경로를 같은 정책으로 추가한다.
4. 프론트 `API_ENDPOINTS`를 `/api/v1`으로 한 번에 전환한다.
5. MockMvc 계약 테스트가 구 경로와 v1 경로의 상태·응답 본문·권한을 대조한다.

nginx rewrite나 서블릿 필터로 URI를 몰래 바꾸지 않는다. 로컬·테스트·운영의 라우팅이 달라지고, Spring Security·감사 로그에 원 요청과 실제 핸들러가 다르게 남기 때문이다.

## 버전 대상과 예외

다음 제품 API는 v1 대상이다.

- 가게, 예약, 리뷰, 즐겨찾기, 광고, 결제, 회원, 사업자 인증
- 채팅·문의·메일함과 관리자 JSON API
- 주소 검색 프록시

다음 경로는 별도 안정성 검토가 필요하다.

- PortOne 웹훅: 외부 콘솔 주소를 바꾸기 전에 구 경로와 v1 경로를 장기간 병행한다.
- OAuth 시작·콜백: `/oauth2/...`는 제품 REST API 버전과 분리한다.
- `/actuator/...`, 정적 자산, SPA 라우트: API v1 대상이 아니다.
- CSP 보고 수집: 브라우저 정책 헤더와 함께 바뀌므로 제품 API 전환과 별도 호환 기간을 둔다.

## 릴리스 순서

1. **v2.6.0** — 현재 혼합 로컬 프리뷰를 최신 `origin/dev` 기준의 깨끗한 통합 공간에 기능별
   manifest로 옮기고, 전체 검증·운영 관문 뒤 릴리스한다. 현재 `dev` 병합이나 운영 반영으로 표시하지 않는다.
2. **후속 2.x 마이너** — v2.6에서 명시적으로 제외한 API v1·AI 답변·MFA·새 광고 정책 등을
   검증 가능한 묶음으로 나눈다. 패치 버전은 이미 배포된 버전의 회귀 수정에만 쓴다.
3. **API v1 도입 2.x 마이너** — `/api/v1`과 `/api`를 병행하고 프론트를 v1로 전환한다. 이 릴리스에서 구 경로를 삭제하지 않는다.
4. **호환 종료 릴리스** — 서버 접근 로그와 외부 연동 확인에서 구 경로 사용이 없고 공지 기간이 끝난 뒤 제거한다. 공개 계약을 깨는 제거라면 앱 메이저 버전으로 처리한다.

## 도입 관문

- 모든 컨트롤러 경로와 프론트 호출 경로의 자동 대조
- 공개/회원/사업자/관리자 권한별 구 경로·v1 경로 MockMvc 계약 테스트
- 로그인 갱신, 파일 업로드, 주소 검색, 결제 준비·검증·환불, PortOne 웹훅 회귀
- Vite 개발 프록시와 nginx 운영 프록시에서 같은 경로 확인
- PC·모바일 핵심 흐름과 production build
- 구 경로 사용량을 구별할 수 있는 서버 로그 또는 메트릭

참고: [Spring Framework 7 API versioning](https://docs.spring.io/spring-framework/reference/web/webmvc/mvc-config/api-version.html)
