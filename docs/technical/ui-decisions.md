# UI 구현 결정

공통 UI에서 반복되는 판단을 모았어요. 일반 규칙은 [디자인 시스템](design-system.md), 작성 방식은 [코드 컨벤션](../rules/code-conventions.md)을 따라요.

## 새로고침

- `RefreshButton`은 `loading` 동안 아이콘을 회전시키고, 별도 3초 쿨다운으로 연타를 막아요.
- 회전 각도를 맞추려고 데이터를 늦추거나 완료 후 계속 돌리지 않아요.

## 조회 결과: 빈 상태와 실패

목록·상세의 읽기 요청은 `DataState`가 빈 결과와 실패를 표시해요. Axios가 안전한 오류 객체로 정규화하고, React Query/훅이 오류를 보존하고, `DataState`가 무채색 아이콘과 문구를 골라요. 서버 원문 오류나 같은 실패의 전역 토스트는 띄우지 않아요.

- 독립 요청이 모두 실패하면 상위 실패 하나로 합치고, 일부 데이터가 남았을 때만 해당 구역에 `compact` 상태를 둬요.
- 조회 재시도는 중립 `다시 불러오기`, 목록 전체 갱신은 `RefreshButton`의 `새로고침`이에요. 대기 중에는 둘 다 같은 자리에서 AntD 회전 화살표를 보여요.
- 폼 검증·mutation·장치 권한 실패는 각 동작에서 따로 처리해요.
- AntD `Alert`·`Empty` 직접 import는 ESLint가 막아요. 새 조회 화면은 `DataState`를 써요.
- 모달 안 조회(QR 코드·사업자 인증 상세)는 최초 조회 `ModalLoading`, 실패는 모달을 닫지 않는 `compact` `DataState`, 재시도 중엔 같은 자리에 `SyncOutlined` 회전 아이콘이에요.
- 리뷰 작성 자격 조회처럼 상세의 일부만 실패하면 기존 내용을 두고 해당 입력 영역 위에 `compact` 상태를 둬요.

## 현재 위치와 거리순

- 홈의 `현재 위치로`와 가게 목록의 `거리순`은 모두 `GET /api/stores`의 `sort=distance&lat=&lng=`를 써요.
- 좌표 반올림·유효 범위 검사는 `utils/distanceSort.js` 한 곳에서 해요. 좌표가 없거나 잘못되면 거리순 요청을 만들지 않아요.
- 홈에서 현재 위치로 목록에 갈 때도 기존 `region` 조건을 유지해요.

## 결제 결과

`/payment/result`는 URL의 성공 문구 대신 본인의 서버 결제 기록을 다시 읽어요. 목록용 `DataState`와 별도 상태 기계예요.

| 상태 | 화면 |
|---|---|
| 조회 중 | `결제 처리 중` |
| 예약 `PAID` 또는 광고 `ACTIVE` 확인 | `결제 완료` |
| 조회 실패, `READY`·`PENDING_PAYMENT` 같은 미확정 | 중립 `상태 다시 확인` + 내역 이동 |
| 명시적 실패·취소 | 내역 화면의 결제 동작으로 안내 |

## 혜택과 광고 타입

혜택은 공개된 가게 소식의 가로 배너 목록이고, 유료 광고 타입과 연결하지 않아요.

- `BADGE`는 화면에서 **노출형**이라고 불러요. 실제 가게 카드·리스트를 상단 우선 정렬하고 작은 광고 표시를 붙여요. API·DB enum은 `BADGE` 그대로예요.
- `BANNER`는 추천에서 시작해 수정 가능한 한 줄 제목·내용과 정사각 대표 이미지 한 장을 쓰는 위젯이에요.
- 혜택 배너는 3.2:1 가로 사진과 텍스트 대비 영역을 써요.

## 채팅

`useChatThread`의 폴링 타이머는 messages 배열 변경에 묶이지 않아요. 최신 커서는 ref로 읽고, 방 로드 뒤 즉시 조회해요.

- 전송 응답과 폴링은 병합 관문을 공유해요. 음수 임시 id는 서버 커서에서 빼요.
- 서버 커서는 양수 id 최댓값이에요.
- 동일 틱 전송 중복과 폴링 중첩은 ref 관문에서 막아요.
- 전송 결과는 현재 방 성공 `true`, 현재 방 실패 `false`, 떠난 방의 늦은 결과 `null`이에요. 호출부는 `ok === false`일 때만 입력을 복원해요.

**방 세대**로 늦은 응답을 걸러요.

- A → B → A도 별도 세대예요. 상태 갱신·onSent·오류 안내·sending 해제가 모두 같은 세대 검사를 지나요.
- 같은 방 재조회도 호출 순간 이전 세대를 무효화해요.
- 새 로드가 성공하기 전에는 폴링·전송하지 않고, 재조회만으로 멱등 재시도 키를 지우지 않아요.
- 읽음 완료 후 배지 캐시 갱신도 방·화면·세션 세대가 같을 때만 해요.

## 계정 전환

- `useAuthStore`가 로그인·로그아웃·서버 인증 주체/역할 변경 때 세션 세대를 바꿔요.
- `SessionQueryProvider`는 세대마다 QueryClient와 화면을 새로 만들고, 같은 경계 안의 AntD 메시지/확인창도 버려요.
- Axios는 요청 호출 순간에 세대를 고정하고, 취소 신호·응답·401 재발급 단계에서도 다시 검사해요.
- 다른 탭에서 auth-storage 주체가 바뀌면 기존 요청을 중단하고 페이지를 다시 열어 서버 인증을 확인해요.
- 같은 계정의 프로필 표시 변경은 `updateUser`, 실제 로그인은 `login`을 써요.
- Login의 인증 완료 효과는 보호 경로의 from/저장된 복귀 경로를 보존해요.

## 폼 오류

- `FormField` 기반 폼은 `useFormErrors`, AntD Form 기반 폼은 Form.Item rules / form.setFields를 써요. 한 폼에 섞지 않아요.
- 오류는 칸 아래에 유지하고 여러 칸의 오류를 한 번에 모아요.
- 필드 입력 오류 토스트는 ESLint가 막아요. 네트워크·권한·결제처럼 작업 전체의 실패 안내는 별개예요.

## 관리 목록

- 사업자 예약은 카드 모양을 유지하면서 서버 페이지네이션을 써요.
- 일부만 받아서 검색하거나 요청 실패를 0건으로 표시하지 않아요.
