# 코드 구조

백엔드는 예약과 권한을 처리하고, 프론트엔드는 화면과 사용자 입력을 담당해요.

## 주요 폴더

~~~text
backend/                 Spring Boot 서버
frontend/src/            React 앱
marketing/               서비스 소개 화면
nginx/                   화면·API 연결 설정
scripts/                 빌드·운영 도구
docs/                    공개 문서
~~~

## 백엔드

Java 패키지의 시작점은 kr.it.reserve예요.

| 영역 | 역할 |
|---|---|
| member·config | 회원·인증·접근 권한 |
| store·reservation·waiting | 가게·예약·웨이팅 |
| payment·advertisement | 예약금·광고·환불 |
| chat·feed·community·promotion | 대화·피드·커뮤니티·가게 소식 |
| file·audit | 파일 접근·삭제 처리·감사 기록 |

각 영역은 요청을 받는 controller, 업무 규칙을 처리하는 service, 저장을 담당하는 repository, 데이터 모델인 entity로 나눠요.

## 프론트엔드

| 폴더 | 역할 |
|---|---|
| pages | 주소별 화면 |
| components | 공통 UI와 기능별 화면 조각 |
| hooks | 조회·저장과 화면 상태 |
| api·services | 서버 요청 |
| store | 로그인 등 공유 상태 |
| styles·assets | 디자인 토큰·CSS·이미지 |
| utils | 날짜·사진·입력 처리 |

주요 화면은 가게 탐색·상세, 예약·웨이팅, 메시지, 마이페이지, 사업자 패널, 관리자 패널이에요. 실제 주소와 접근 권한은 [App.jsx](../../frontend/src/App.jsx)에서 확인할 수 있어요.

## 통합검색

검색 화면은 기존 메뉴·도움말과 공개 가게·혜택·피드, 본인 예약·웨이팅·메시지를 종류별로 보여줘요. 메뉴는 역할에 맞는 기존 화면으로 연결하고, 데이터 검색은 서버에서 공개 여부·소유권·표시 기간을 확인해요. 탐색·웨이팅의 목록 검색창은 해당 목록의 필터로 유지해요.

입력 중에는 앱 안의 메뉴·별칭만 찾고, 검색을 확정할 때만 서버를 조회해요. 정상 세션의 확정 검색은 공개 결과와 로그인한 회원의 본인 결과를 최대 두 요청으로 묶어요. 명확한 메뉴 별칭은 서버 조회 없이 해당 메뉴를 안내해요. 결과가 있는 종류만 표시하며 검색어를 비우면 서비스 선택·빠른 검색·최근 검색을 보여줘요.

목록의 상단 검색어 표시는 해당 목록의 검색 입력으로 연결하고, 별도 검색 아이콘은 검색어를 넘기지 않고 통합검색을 열어요. 관리자·사업자 목록의 검색은 각 목록의 조회 조건과 권한 범위로 처리해요.

가게 목록의 MySQL FULLTEXT/ngram 경로는 실제 색인·파서·컬럼을 확인하고 원문 검색의 일치 조건을 유지해요. 통합검색도 같은 색인을 재사용할 수 있지만 `search.store.unified-fulltext-enabled`는 기본 `false`예요. 이 경로는 누락 확인을 위한 전체 건수 비교가 추가되므로, 활성화는 실제 조회 비용과 실행계획을 확인한 뒤 판단해요. 기존 `search.store.fulltext-enabled`도 켜져 있어야 하며 색인을 앱이 자동 생성하지 않아요.

검색은 기존 앱과 MySQL을 사용하며 별도 검색 서버나 공유 개인 데이터 색인을 만들지 않아요. 결과를 선택하면 기존 상세 권한 확인을 거쳐 이동하고, 조회만으로 예약·접수·대화방을 만들지 않아요.

## 설정

- 서버 설정은 backend/src/main/resources의 application 설정 파일에서 읽어요.
- 브라우저에 필요한 공개 설정만 VITE_ 환경 변수로 전달해요.
- 비밀번호·암호화 키·공급자 비밀 값은 서버 환경에만 두어요.
- 개발·시험·운영은 별도 프로필과 저장 경로를 사용해요.
