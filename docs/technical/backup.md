# 백업과 복구

백업은 장애나 잘못된 변경이 생겼을 때 데이터를 되찾기 위한 복구 수단이에요.

## 백업 대상

| 대상 | 보관 방식 |
|---|---|
| MySQL | 정기 덤프를 서버와 비공개 S3에 보관 |
| 암호화 사진·첨부파일 | 원본 파일과 해당 복호화 키를 함께 관리 |
| 실행 버전과 설정 | 데이터 구조와 호환되는 앱·화면·설정을 보관 |

백업에 성공했다는 사실만으로 복구가 가능한 것은 아니에요. 별도 환경에서 복원하고 앱이 데이터를 읽을 수 있는지 확인해요.

## 접근과 보관

- 앱·백업·데이터 구조 변경은 서로 다른 권한을 사용해요.
- 백업 버킷은 비공개로 두고 암호화와 보관기간을 적용해요.
- 파일의 해시를 비교해 내려받은 백업이 원본과 같은지 확인해요.
- 복구에 필요한 암호화 키는 백업 파일과 분리해 보호해요.
- 보관기간이 지나도 현재 복구에 필요한 묶음과 대응 키는 함께 관리해요.

## 복구 원칙

복구 전에 데이터 쓰기를 멈추고 현재 상태를 보존해요. 복원 후에는 원래 서버와 호환되는 버전을 시작하고, API가 정상 JSON을 응답하는지 확인해요. 확인에 실패하면 서비스를 정상화한 것으로 처리하지 않아요.
