> 통합·운영 반영을 구분한다. 단계별 작업량이 달라 임의 완료율은 붙이지 않는다.
> 2026-09-14 안정화·실제 계정 관찰·최신 dev 조회/승인 경계는 [최신 체크포인트](stabilization-progress-2026-09-14.md)를 우선한다.
> 이후 혜택 기획전 첫 UI·54개 지정 회귀·중간 폭 실측/공개 소식404는 [혜택 체크포인트](benefits-campaign-progress-2026-09-14.md)다.
> 아래 9월 13일 검사 수치는 보존 이력이며 새 배치의 검사 결과가 아니다.

## 이번 후속 배치

- 공개 가게 목록을 서버 페이지네이션 **12건/페이지**로 전환했다. 기존 공통 카드와
  PC·모바일 오른쪽 종류/정렬 필터는 유지하고 디자인 시스템의 회색 AntD 페이지 번호를 재사용한다.
- 메신저를 내부 하단 **홈 / 대화 / 설정**으로 정리했다. 홈은 관리자 문의·최근 대화,
  설정은 실제 계정·기존 PC 세션 알림이며 PC 패널은 모든 내부 화면에서420px이다. 런처를 여는 것만으로 고객지원 방을 만들거나
  읽음 처리하지 않는다. 최근 대화와 고객지원을 사용자가 직접 고른다.
- 프로필 메뉴의 중복 메시지 항목을 제거했다. 진입은 PC 패널·모바일 `/messages` 런처를 사용한다.
- 대화별 입력 초안은 세션 메모리 안에서 최대 **20개 × 2000자**로 보관한다.
  새로고침·로그아웃·재로그인·계정/역할 전환 때 폐기하며 DB나 브라우저 영구 저장소에 쓰지 않는다.
- 사장님 수동 답변 문구를 추가했다. 사용자가 입력칸에 넣고 직접 보낸다. AI·자동 전송이나
  예약 가능 여부·가격·환불 조건의 자동 확정이 아니다.
- 선택형 PC 세션 알림을 추가했다. 기본 OFF이며 명시적 클릭으로 권한을 요청한다.
  열린 대화에서 새로 받은 메시지를 대상으로 하며 이름·가게명·본문을 OS 알림에 넣지 않는다.
- 관리자 고객지원 polling이 가게 대화방을 조회·읽음 처리하지 못하도록 SUPPORT 타입 관문을 추가했다.

## 큰 단계별 남은 일

후속 디자인 요청: 공통 헤더의 PC·모바일 전체 워드마크+검색 아이콘에 이어 소식·혜택 안내 v1을 연결했다.
현재 25 URL의 로딩/오류 점검은 [전수 점검](skeleton-audit-2026-09-13.md)이다.
인기 검색어·실제 쿠폰·웨이팅·피드·기존 페이지/디자인 시스템의 대규모 점진 전환은
[디자인 전환 계획](design-evolution-plan-2026-09-13.md)에 남아 있다. 백로그를 구현 완료로 계산하지 않는다.

추가 후속 요청: 메시지 런처의 흰 배경·브랜드 블루 아이콘/X·선택형 사진을 로컬 구현했다.
광고 UI·플로팅 영역 우선순위·저장소 도입 판단은 [검토 문서](channel-style-advertising-and-storage-review-2026-09-13.md)의
제안 단계다. 현재 MySQL 유지와 검색 전체 로딩/광고 집계 유실 가능성의 선행 검토를 권고하며 새 DB는 도입하지 않았다.
런처 확인은 명시적 4개 테스트와 인증/API 없는 실제 시각 컴포넌트 미리보기다. 아래 기존 실행 이력과 합쳐 전체 E2E로 계산하지 않는다.

| 큰 단계 | 현재 로컬 구현 | 다음 완료 조건 |
|---|---|---|
| 0. XSS·이미지 소유권 | DOM/textContent 지도 링크, 기존 이미지 유지·삭제 prefix/소유권 검증 | 최신 dev 통합·보안 회귀 확인·승인된 운영 반영. 운영 과거 변조 데이터와 CSP는 별도 확인 |

0·1의 주요 구현은 기존 프리뷰 작업을 이어받은 것이다. 이번 후속 배치에서 해당 전체 영역을
재검사한 것은 아니다. 날짜별 실행 이력은 [품질 점검](../../quality-roadmap.md)에 보존한다.

## 개발 순서와 승인 관문

개발은 **기준선 정리 → 앱형 탐색 → MessengerShell → 텍스트 가게 채팅 → 확장** 흐름을 유지한다.
백업 구축을 로컬 디자인·기능 개발이나 dev 통합의 선행 조건으로 만들지 않는다. 다만
`authVersion`·동의 이력·outbox도 스키마 변경이므로, **첫 DB 변경 운영 배포 전에는 검증된 백업과
`reserve_restore_*` 격리 복원을 완료해야 한다.** 스냅샷 상태 조회도 실제 확인 전에는 완료로 표시하지 않는다.

| 관문 | 필요한 결정/증거 | 경계 |
|---|---|---|
| 외부 알림 | 채널/제공자, 수신 동의·수신 거부, 조용한 시간, 재시도·중복 방지·비용 | PC 세션 알림을 외부 push 완료로 취급하지 않음. 외부 발송·계정 설정은 별도 승인 |
| 비공개 첨부 | private 저장소·IAM, 방 참여자별 upload/download 권한, 바이트 검증·크기 제한, 보존/삭제·신고 hold | 공개 가게 사진 경로를 채팅 첨부에 재사용하지 않음. 버킷/IAM·운영 저장은 별도 승인 |
| AI 답변 초안 | 제공자, 전송할 대화 범위·개인정보 최소화/동의, 보존 조건·비용 상한 | 초안만 제공하고 사장님이 확인·전송. 자동 예약·결제·환불 실행은 범위 밖 |
| 채팅 보존 | 일반 대화·차단·신고 자료 각각의 기간과 삭제 예외 승인 | 미정 보존기간을 임의 hard delete로 구현하지 않음 |
| 통합·배포 | 최신 dev 통합과 위험도별 최종 확인, DB 변경 배포 전 백업/격리 복원 | 커밋·PR·머지·태그·배포는 현재 대화의 명시적 승인 뒤 수행 |

세부 계약: [디자인 시스템](../../design-system.md), [검색 UI](../../search-ui.md),
[통합 메시지](../../messaging.md), [백업·복구](../../backup.md).

## 이번에 실행한 확인과 한계

최신 메신저/홈 정리는 명시 frontend 고유63개(중복 제외), 변경12개 ESLint, CSS 파서,
Vite build/budget, 동결 ZIP 해시와 PC/모바일 화면 확인을 실행했다. footer·제목 위계와
과거 메시지의 늦은 성공/실패4케이스도 포함한다. 메신저 캡처는 인증/API 없는 시각 fixture이고
실제 계정 왕복 대화나 OS 알림/위치 권한 승인은 실행하지 않았다.
[최신 구현·실측·정확한 실행 묶음](messenger-home-refinement-2026-09-13.md).

아래는 앞선 목록/메신저 배치의 실행 이력이다. 최신 소식/로딩 배치는 명시 frontend 고유 117개와
public promotion backend 8개, Vite build/budget, 스냅샷 해시 및 공개 실제 0건 GET/PC·모바일 확인으로
별도 기록했다. [정확한 실행 묶음·예시/실데이터 경계](../../../design-system/visuals/2026-09-13-benefits-loading/README.md).
어느 배치도 전체 suite/실제 두 계정 E2E/운영 반영 완료가 아니다.

- 명시적 프론트 회귀: 목록 **21개**, 메신저 상태/초안 **15개**, 알림 유틸리티 **29개**,
  메신저 화면/런처 **14개** 통과. 서로 다른 명시적 실행 결과이며 전체 프론트 스위트가 아니다.
- 선택한 `StoreChatServiceTest` **8개** 통과. Mockito 서비스 검사이며 운영 DB나 실제 두 계정 대화가 아니다.
- 변경 프론트 파일 ESLint, CSS parser guard와 변경 경로 `git diff --check` 확인.
- 직접 브라우저 확인: 공개 `/stores` PC **1440×900**, 모바일 **390×844**에서 오른쪽 필터,
  기존 카드·회색 페이지 번호·가로 넘침 없음 확인. 실제 로컬 데이터는 가게 2개라 1페이지이며,
  잘못된 `page=2` 진입의 유효 페이지 보정도 확인했다. 여러 페이지 데이터는 목록 회귀의 fixture 검사다.
- 로그인된 메신저의 실제 두 계정 대화와 OS 권한/알림 전달은 실행하지 않았다.
  화면·알림 회귀는 mock 기반이다. 이 과거 목록/알림 배치에서는 전체 스위트·production build·전체 viewport 행렬을 실행하지 않았다.
  최신 정리의 build/budget은 위 별도 기록이다.
- 이번 배치에서 Git history·AWS·서버·운영 DB·PortOne 변경과 외부 알림/AI 발송은 하지 않았다.
