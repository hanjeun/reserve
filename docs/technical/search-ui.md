# 검색 전용 화면과 헤더

2026-09-13~14 로컬 프리뷰. 운영 배포 증거가 아니다.

## 화면과 진입

- 주요 화면의 공통 헤더: PC·모바일은 원래 PC의 Pretendard·22px·850 굵기·-0.8px 자간 전체 RESERVE 워드마크를 공유한다. 오른쪽은 검색 아이콘 → 둥근 프로필 사진이다. 검색어가 있는 `/stores` 결과에서는 아이콘 대신 현재 검색어를 보여주는 검색 진입 필드를 두며, PC는 검색어 필드를 검색 화면 입력칸과 같은 자리(화면 가운데·최대 560px, [로고][검색창][계정] 3칸 격자)에 두고 전체 워드마크를 유지하며, 768px 미만에서는 로고를 숨기고 뒤로가기와 검색어 필드만 둔다(2026-09-23 — 한 글자 R 로고 제거). 다른 모바일 화면과 모든 PC 화면의 전체 워드마크는 유지한다. 로고는 홈으로 이동한다. 탐색 루트가 아닌 분야·검색 결과 목록과 상세·계정 화면에는 **PC와 모바일 모두** 공통 뒤로가기를 추가한다. 추가 예약/관심/알림/메뉴 아이콘은 계획 후보일 뿐 아직 넣지 않는다.
- 헤더 검색 아이콘은 공용 `/search` 라우트로 이동하는 링크다. 가게 목록을 먼저 열지 않아도 검색을 시작할 수 있고, 실제 입력은 전용 검색 화면에서 한다. 헤더에는 입력 모양 검색창을 두지 않는다.
- 공통 헤더는 모든 페이지에서 높이 64px와 동일한 반응형 여백을 사용한다. 검색 아이콘은 44×44px이며 로고·프로필·모바일 뒤로가기 동작 영역도 44px 높이를 유지한다. 중립 opacity hover·키보드 포커스 링을 공통 CSS에서 적용한다. 헤더·홈의 일반 로고/텍스트 scale 눌림은 제거했고 사진/3D 효과는 보존한다. 다른 페이지의 기존 pressed 스타일은 점진 전환 대상이며 일괄 교체한 것은 아니다. scroll-snap 메인 배너는 축소하지 않는 별도 패턴이다.
- 비로그인 헤더의 `로그인`과 `시작하기`는 모바일 767px 이하에서 기존 4px 컨테이너 간격과 버튼의 13px 안쪽 여백을 그대로 유지한다. PC 900px 이상에서는 로그인 버튼의 좁은 4px 여백 때문에 CTA가 붙어 보이지 않도록 두 버튼 사이만 12px로 둔다. 버튼 크기·모바일 비율·검색 아이콘 간격은 바꾸지 않는다.
- 프로필 메뉴와 중복되던 고정 하단 페이지 메뉴 및 높이 보정용 공백은 제거했다. 법적 고지·문의 푸터, 사진 배너·바로가기·추천 목록의 반응형 배치는 유지한다.
- 검색 페이지는 고정된 480px 앱 프레임을 사용하지 않는다. 본문은 최대 960px이며, 모바일 20px(아주 좁으면 16px)·태블릿/PC 24px 여백을 사용한다. PC 자체 검색 필드는 공통 헤더와 같은 최대 560px이며, 왼쪽에 취소와 같은 폭의 빈 칸을 둔 [빈 칸][입력칸][취소] 격자로 입력칸 자체를 화면 가운데에 둔다(결과 헤더 검색창과 같은 자리). 전역 헤더·탭·푸터는 숨기고 자체 입력·취소 행을 사용한다. 이 행도 64px 높이로 고정하여 PC에서 96px로 늘어나지 않는다.
- 분야 선택은 모바일 3열/2행, 768px 이상 6열/1행으로 배치한다. 아이콘의 물체별 광학 크기는 유지하며 화면이 넓다고 과하게 확대하지 않는다.
- 전용 검색 입력만 44px 높이/100px 반경의 pill 형태다. 실제 입력 글꼴은 16px, 지우기·취소 동작 영역은 44px이다. 입력 포커스는 파란 외곽 링 대신 중립색 테두리로 표시한다. 기존 테마 CSS 색 토큰을 유지한다.
- 목록 본문의 중복 검색 입력과 파란 검색 버튼은 제거했다. 검색 결과의 헤더 필드는 현재 검색어를 한 줄로 보여주며 누르면 `/search?keyword=…`로 입력을 복원한다. 실제 편집·제출은 기존 검색 화면에서만 처리하며 결과 헤더에 별도 입력 로직을 만들지 않는다. 수정 취소는 기존 결과의 필터·보기·페이지를 복원한다.
- 가게 목록은 큰 제목·소개 문구 없이 오른쪽의 분야·정렬 메뉴로 시작한다. PC·모바일 모두 두 메뉴는 나란히 오른쪽 정렬하고 가게 수는 왼쪽에 둔다. 페이지 제목은 화면 읽기 프로그램용 `h1`으로만 남기고, 가게 카드 크기는 유지한다.
- 목록 필터 왼쪽의 아이콘으로 기존 원본 비율 사진형과 정사각 사진·정보를 나란히 놓는 목록형을 전환한다. 아이콘은 다음에 전환할 보기 모양으로 바뀐다. 사진형은 `view=cards`, 목록형은 `view=list`로 URL에 남으며, 보기만 바꾸면 현재 페이지·필터를 유지하고 목록 API를 다시 요청하지 않는다. 초기 조회·재조회 스켈레톤도 선택한 보기에 맞추고, 조회 중에는 아이콘을 잠근다. [구현·검증 기록](history/2026-09-preview/store-list-view-modes-2026-09-14.md)
- 결과는 서버에서 12건씩 받고 하단에 기존 AntD 회색 페이지네이션을 둔다. PC·모바일 모두 같은 페이지 방식이며, URL의 검색·분야·정렬은 유지한다. 조건 변경 시 첫 페이지로 돌아가고 무한 스크롤 sentinel와 완료 문구는 제거했다.
- 주요 화면의 `홈 · 탐색 · 혜택 · 웨이팅 · 피드` 탭은 공통 레이아웃에 한 번 두며 PC·모바일 모두 44px 높이다. `/stores` 전체 탐색(정렬 포함)은 탭을 유지하고 분야/검색 결과는 하위 화면으로 판정해 탭을 숨긴다. 공통 Header 뒤로가기는 PC·모바일 모두 기존 `useGoBack`을 사용해 이전 화면으로, 앱 히스토리가 없으면 목록/홈으로 이동한다. 상세 본문에 별도 중복 뒤로가기는 표시하지 않는다.
- 혜택은 실제 공개 홍보글을 읽는 소식·혜택 안내 v1과 `/benefits/:id` 상세를 연결했다. 실제 쿠폰 발급/사용 모델은 없으며 최신 기획전 v2 전환은 [후속 계획 §11](history/2026-09-preview/design-evolution-plan-2026-09-13.md)이다. 웨이팅·피드는 준비 화면이며 원격 대기 접수·게시 기능은 구현하지 않았다.
- 로그인 전 프로필 메뉴에는 로그인·회원가입·탐색 링크가 있다. 로그인 후 프로필 사진, 이용 동의 경계, 역할별 계정 메뉴, 로그아웃 동작은 기존 구현을 유지한다. 보호된 링크는 기존 PrivateRoute를 거친다.

## 동작과 데이터 경계

- 입력에 포커스를 둔다. 검색 화면 왼쪽 아이콘은 `type=submit` 실행 버튼이며 Enter·모바일 키보드 검색과 같은 form 제출 동작을 사용한다. 앞뒤 공백을 제거한 검색어를 기존 `/stores?keyword=…` 결과 화면에 넘긴다. 빈 값은 제출하지 않고, 한글 조합 확정 Enter는 검색을 실행하지 않는다.
- 입력 변경만으로 검색 API 요청을 하지 않는다. 새 백엔드·검색 서버·DB 테이블을 만들지 않는다.
- 검색어 지우기는 입력만 비우고 포커스를 유지한다. 취소/입력칸의 Escape는 헤더를 통해 들어온 경우 이전 화면으로, 직접 접근한 경우 홈으로 이동한다.
- 홈·검색 분야 아이콘은 `constants/discovery.js`의 이미지/광학 크기 정보를 공유한다.
- 빠른 검색 문구는 안내용 예시다. 실측 인기 순위·현재 위치·개인화 추천으로 표현하지 않는다.
- 최근 검색어 저장, 서버 자동완성, 인기 검색 집계는 이번에 구현하지 않았다. 입력 내용을 localStorage나 DB에 새로 저장하지 않는다.
- 인기 검색어는 [디자인 전환 계획](history/2026-09-preview/design-evolution-plan-2026-09-13.md)의 후속 백로그로만 추가했다. 실제 집계·갱신 시각·공개/보존 기준 없이 현재 빠른 검색 예시를 인기 순위로 바꾸지 않는다.
- `/search`는 기존 `useRouteSeo`의 비색인 기본 정책을 따른다. 서버의 X-Robots-Tag 정책과 실제 운영 URL 확인은 배포 준비 단계에서 별도로 맞춰야 한다.

## 접근성과 테마

- 입력에 명시적인 검색 라벨과 `role=search`, 지우기 버튼에 라벨을 둔다. 빈 검색어는 제출하지 않고 입력에 포커스를 유지한다.
- 공통 헤더·탐색 탭·전용 검색의 링크/버튼은 중립색 2px 키보드 포커스 링과 기존 키보드 동작을 사용한다. 검색 결과 링크와 메뉴의 인증 경계를 우회하지 않는다.
- 목록의 분야·정렬은 같은 투명 텍스트 스타일의 입력 없는 `FilterMenu`로 오른쪽에 나란히 둔다. 보이는 면은 32px, 버튼 동작 영역은 44px다. 옵션 메뉴는 최소 128px 폭·4px 여백·10px 반경, 항목은 모바일 40px·PC 36px 최소 높이다. 마우스·터치에는 외곽 링/축소를 적용하지 않고 키보드 포커스에는 중립색 2px 링을 둔다. 선택 체크·로딩·비활성 상태는 보존하며 거리순의 기존 위치 요청 동작은 바꾸지 않는다.
- 로고의 홈 smooth scroll은 모션 감소 설정을 따른다.
- 검색 결과 필드는 링크로 올바르게 노출하고 ‘검색어 수정: …’ 라벨·말줄임·전체 검색어 title을 제공한다. 44px 높이·16px 글꼴·최대 560px의 유동 폭과 기존 테마/포커스 토큰을 사용한다. 검색 실행 아이콘도 44px 영역·명시적 라벨·키보드 포커스 링을 갖는다. [검색 결과·평점 통일 기록](history/2026-09-preview/search-results-and-rating-zero-2026-09-14.md)
- 시스템 테마 전환에서 `useTheme`가 새 snapshot을 알리도록 보정했다. CSS 화면과 AntD 메뉴 algorithm이 함께 바뀌어야 한다.

### 검색·자동 이동의 페이지 전환 (2026-09-23)

- 검색 화면은 열 때 본문이 올라오고, 취소·Esc 로 닫을 때 내려간다(들어가기·나가기 짝). 검색 실행·빠른 검색은 결과가 바로 보이고 스켈레톤으로 채운다. 닫힌 뒤의 원래 화면·결과 화면에는 옆으로 밀리는 페이지 전환을 걸지 않는다 — 검색은 화면 이동이 아니라 검색창을 닫는 것이다.
- `replace` 이동은 기본적으로 전환하지 않는다: 권한·세션 안전장치(남의 예약·변경 불가 예약 → 내 예약, 권한 없음 → 홈, 이미 로그인됨), 소셜 로그인 콜백, 메신저 내부 주소 정리.
- 사용자가 끝낸 흐름은 호출부가 의미에 맞는 방향을 `reserveRouteMotion` 으로 명시한다.
  | 이동 | 방향 |
  |---|---|
  | 로그아웃·탈퇴·회원가입 완료 → 홈 | 왼쪽에서(로고 → 홈과 같은 방향) |
  | 로그인 필요 페이지 → 로그인, 비밀번호 변경 → 다시 로그인 | 오른쪽에서(가던 길이 이어짐) |
  | 로그인 성공 → 막혔던 페이지 / 소셜 약관 동의 → 가려던 페이지 | 오른쪽에서 |
  | 스스로 로그인 → 있던 페이지, 가려던 곳이 없으면 홈 | 왼쪽에서(돌아감) |
- 같은 경로 안의 변화(필터·정렬·페이지·지역·보기 방식·패널 탭)는 원래부터 전환하지 않는다. 판정은 `routeEntryMotion.js` 한 곳에서 한다.
- 들어가기와 나가기는 짝을 맞춘다: 메신저 목록 → 대화(오른쪽에서) ↔ 뒤로(오른쪽으로), 헤더 뒤로가기 버튼 나타남 ↔ 눌러서 사라짐, 광고 신청 다음 단계(오른쪽에서) ↔ 이전 단계(왼쪽에서).
