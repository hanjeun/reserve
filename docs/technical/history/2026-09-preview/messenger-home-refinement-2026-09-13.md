# 메신저·홈 정리 기록

> 2026-09-13 `local-preview-all-changes` 로컬 구현 기준. 운영 반영·실제 두 계정 대화와 구분한다.

## 이번에 구현한 것

- 메신저의 상단 홈/대화 선택, 긴 소개, 알림·초안 안내, 별도 받은 문의 바로가기를 홈에서 제거했다.
  내부 하단 메뉴를 **홈 · 대화 · 설정**으로 모았다. 홈에는 관리자 문의 안내 카드와 실제 최근 대화 최대2건만 둔다.
- ‘관리자에게 문의’는 기존 SUPPORT 대화를 명시적으로 선택하는 동작이다. 홈을 열거나 설정/대화 메뉴를
  누르는 것만으로 고객지원 방을 만들거나 읽음 처리하지 않는다. 안내 카드를 실제 수신 메시지로 저장하지 않는다.
- 최근 대화와 목록은 같은 `MessengerConversationRow`를 사용한다. 실제 상대·미리보기·시각·방별 unread를 표시한다.
  목록에서 실제로 불러온 일부 페이지의 unread 합을 전체 배지로 표시하지 않는다. 0건에 가짜 고객지원 이력도 넣지 않는다.
- 설정에 실제 로그인 계정의 이름/이메일과 기존 내 정보 관리 링크, 선택형 PC 세션 알림 및 초안 보존 안내를 옮겼다.
  구현되지 않은 번역·언어·알림음·외부 알림 설정을 장식용 토글로 넣지 않았다.
- PC 플로팅 패널은 모든 내부 화면에서420px이다. 패널/모바일에서 대화를 고르면 목록과 하단 메뉴를
  대화 화면/입력 영역으로 교체한다. 내부 뒤로 가기로 목록에 돌아온다. PC 전용 `/messages`의 목록+대화 2열은 보존한다.
  패널의 숨겨진 목록을 DOM에서도 제거해 기존 focus trap에 보이지 않는 목록 버튼이 포함되지 않게 했다.
- 모바일/페이지에서는 공통 헤더 아래 RESERVE 브랜드를 한 번 더 표시하지 않는다. PC 패널에는 내부 브랜드를 유지한다.
- 홈 우측 ‘서비스 둘러보기’를 **현재 위치로**로 변경했다. 클릭 시 기존 위치 훅과 거리순 가게 목록을 사용한다.
  요청 중 중복 클릭을 막고, 위치 거부/실패/미지원 처리를 유지한다. 위치를 얻지 못했지만 계정 저장 좌표가 있으면
  저장 위치 기준임을 알린 뒤 사용한다. 위치 요청은 자동 실행하지 않는다.
- 일반 워드마크·검색/뒤로 가기·탐색 탭·지역/현재 위치·전체 보기·텍스트 안내의 scale을 제거했다.
  중립색/opacity hover와 키보드 focus는 남긴다. 메신저 일반 공통 버튼도 scale 없이 동작한다.
  프로필 사진·3D 바로가기·배너/가게 사진의 기존 hover/누름 효과는 보존한다.
- 홈 공개 섹션 간격을 의미 있는 홈 패턴에만 정리했다. 업무 폼·표·스켈레톤의 모든 회색 면을 일괄 변경하지 않는다.

## 상대별 대화와 보존 범위

사용자 확인은 **여러 상대와 각각 대화**이며 그룹 채팅이 아니다. 기존 손님↔관리자 SUPPORT와
손님↔개별 가게 STORE 대화, 사장님의 받은 문의 목록을 사용한다. 그룹 참여자/초대·직원 권한·담당자 배정·
사용자 간 임의 DM·동일 상대와 주제별 새 방을 이번에 추가하지 않았다.

기존 MEMBER/OWNER 전송 가능 여부·차단/신고·참여자 검사·polling·읽음·대화별 세션 초안 관문은 유지한다.
계정/역할 전환, 새로고침·로그아웃 때 초안을 폐기하는 정책도 바꾸지 않는다. 메뉴 이동 중 선택·초안은 보존하되
활성 대화는 해제한다. 홈/설정 화면에서 방을 자동 열거나 메시지를 전송하지 않는다.

독립 검토에서 기존 과거 메시지 조회의 늦은 응답이 대화 전환 후 다른 화면에 반영될 수 있는 위험을 발견했다.
요청 당시 `threadKey`/`roomId`의 committed 세대를 캡처해 성공·오류·finally를 모두 검사하도록 수정했다.
다른 대화/홈/설정으로 이동할 때 이전 스크롤 복원값도 폐기한다. 같은 방에 다시 들어와도 옛 요청을 재사용하지 않는다.
늦은 A 응답이 B의 메시지나 B의 진행 중 조회 상태를 변경하지 않도록 회귀 검사했다.

## 참고와 실제 실측

[채널톡 공식 페이지](https://channel.io/kr)의 공개 위젯에서 홈 안내 카드, 상대별 대화 행,
하단 홈/대화/설정과 독립 스크롤 구조를 확인했다. 이 기기에서 참고 footer는 약60px,
메뉴 조작 영역은50px, 레이블은10px이었다. 외부 SDK·브랜드·사진·코드를 가져온 것이 아니라
RESERVE의 현재 색·공통 컴포넌트·접근성 규칙으로 구조를 재구성했다.

| 확인 대상 | 현재 DOM 측정 / 경계 |
|---|---|
| PC 시각 미리보기 1440×900 | 패널420×620px, footer 약62.8px, 메뉴 버튼54px, 대화 행 최소78px |
| 모바일 시각 미리보기 390×844 | 공통 헤더 fixture64px + 메신저780px, footer1개, 가로 넘침0px |
| 작은 모바일 320×568 | 메뉴 버튼54px, footer 약62.8px, 가로 넘침0px |
| 모바일 개별 대화 | 하단 메뉴0개, 별도 입력 영역 하단 유지. 입력은 fixture에서 비활성/전송 없음 |
| 다크 설정 | 기존 다크 토큰 사용, footer `rgb(26,29,33)`, 본문 `rgb(232,234,237)` |
| 실제 공개 홈 PC/모바일 | 헤더64px+탐색44px 유지. PC 배너1200×480px, 모바일335.2×223.46px 유지 |

메신저 사진은 인증/API 없는 시각 fixture다. 실제 `MessengerHome`, `MessengerFooter`, `MessengerSettings`,
`MessengerConversationRow`, `ChatBubbleList`와 현재 CSS를 렌더한다. 모바일 공통 헤더는64px 시각 대역이며
실제 계정 메뉴/뒤로 가기 라우팅을 캡처한 것이 아니다. PC 설정 fixture도 알림 control을 주입하지 않아
알림 권한/켜기 기능을 시각 증거로 주장하지 않는다. 실제 기능은 mock 기반 컴포넌트 검사로 구분한다.

홈 간격은 `--reserve-home-section-spacing:20px`, `--reserve-home-content-spacing:16px`,
`--reserve-home-divider-size:4px`이다.

| 홈의 같은 종류 간격 | 이전 | 현재 |
|---|---|---|
| 바로가기 위/아래 | 모바일20/24, PC24/28px |20/16px |
| 바로가기 행 간격 |18px |16px |
| 추천 섹션 회색 구분선 |8px |4px |
| 추천 위/아래 |24/30px |20/20px |
| 추천 제목 아래 |18px |16px |

배너 원본 사진·비율·현재/전체 번호 및 기존 가게 카드/페이지 번호는 이번 배치에서 변경하지 않았다.
위 PC/모바일 공개 홈 측정은 비로그인 홈의 확인이며 인증된 메신저 E2E 증거가 아니다.

## 다음 시안 — 이번엔 계획만

- 배너 번호는 유지하되 작은 시각 표시와44px 이상 조작 영역을 분리하는 안을 권한다.
  현재 ‘다음 배너’와 전체 배너 모음 보기는 의미가 다르다. 모음을 만들기 전에 ‘전체’를 붙이지 않는다.
- 지역 설정은 사용자 제공 캐치테이블 화면을 토대로 **주요 지역 → 시·도/세부 지역 → 초기화/적용**을 제안한다.
  이번에는 해당 모달의 최신 Catchtable DOM/CSS를 실측한 것은 아니다. PC 모달/모바일 시트를 먼저 비교하고
  지역 코드·가게 데이터 보정·필터 API를 정의한 뒤 구현한다. 현재 전체 지역은 `/stores` 링크로 유지한다.
- 모든 회색 여백을 전역으로 줄이지 않는다. 같은 의미의 공개 섹션을 두 번째 화면에서 적용·검증한 뒤 추출한다.

자세한 동작·데이터 관문은 [전환 계획 §9](design-evolution-plan-2026-09-13.md)에 등록했다.
실제 쿠폰·인기 검색어·웨이팅·피드·광고 및 새 DB는 별도 백로그이고 이번 화면 정리로 완료 처리하지 않는다.

## 실행한 확인과 남은 경계

- 메신저4파일 명시 테스트47개 통과: Content13, Shell4, 하단 메뉴/설정15, 상태/초안15.
- 후속 최신 Content·홈·헤더3파일 테스트23개 통과: Content13, 홈6, 헤더4.
  Content13은 중복 실행이므로 위47과 더해70개로 계산하지 않는다. 전체 frontend suite는 실행하지 않았다.
- 최종 하단 메뉴/설정/홈 제목 검사17개 통과(기존15+브랜드·제목 위계2).
  Content17개 통과(기존13+대화 A→B와 A→설정→A의 늦은 성공/실패4). B의 pending 조회 상태도 보호한다.
  이 배치의 서로 다른 frontend 테스트는 중복 제외63개이며 단일63개 실행이나 전체 E2E가 아니다.
  독립 agent의 기본 로더는 환경 접근권한으로 시작 실패했으나 원본 설정 native loader로17개 통과했고,
  root에서도 기존 기본 명령으로 같은17개를 통과했다. 설정 파일은 변경하지 않았다.
- 최종 변경12개 JS/JSX 파일 ESLint 통과. CSS2파일587규칙 파서 검사를 통과했다.
- 최종 Vite production build 및 번들 예산 검사 통과: 초기 JS321.0KiB gzip(350KiB 이하),
  최대 JS563.5KiB(600KiB 이하). 변경 경로 `git diff --check`와 새 기록의 로컬 링크13개를 확인했다.
- 실제 공개 홈과 인증/API 없는 메신저 fixture의 PC·모바일 DOM/캡처를 확인했다.
  임시 viewport/emulation을 복원하고 이 작업에서 만든 참고/fixture 탭을 닫았다.
- 기존 동결 ZIP SHA-256은 `02d5809dabf319ed1778140210e4303862b5f5a37b0b5ef6dd5d880514af536e`로 재확인했다.
  기존 Core 전체를 교체하거나108개 소스 기준선 ZIP을 덮어쓰지 않았다.
- 실제 두 계정 왕복 대화·재접속, 실제 위치 권한 승인, OS 알림 전달, 운영 DB/백엔드 통합은 실행하지 않았다.
  커밋·PR·브랜치 변경·배포·AWS·PortOne·외부 발송도 하지 않았다.

사용한 지침은 RESERVE, 디자인 시스템, 컴퓨터 사용/화면 검증 스킬과 메신저/디자인/홈/로드맵 관련 문서다.
모든 설치 스킬이나 관련 없는 문서를 전수 읽었다는 뜻은 아니다. 공통 규칙을 현재 실제 소스와 비교해
기존 기능/영구 저장 경계를 유지하고 RESERVE 전용 패턴만 점진 변경했다.

시각 캡처와 실행/fixture 경계: [캡처 안내](../../../design-system/visuals/2026-09-13-messenger-refinement/README.md).

2026-09-14 후속 보고에서는 홈 메인 배너의 눌림 scale을 제거했다. 작은 사진/3D 효과와 원본 비율·번호는
보존한다. 모바일 등록·수정/확인 모달 보정과 새 검사 범위는 [후속 기록](layout-regressions-2026-09-14.md)이다.
