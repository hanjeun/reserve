# Git 워크플로

## 브랜치

| 브랜치 | 역할 |
|---|---|
| feature·fix·chore | 기능·수정·관리 작업 |
| dev | 개발 통합 |
| main | 운영 배포 |

main 변경은 PR과 필수 검사를 거쳐요. 보호 규칙을 우회하지 않아요.

## 머지

- 작업 브랜치 → dev: merge commit
- dev → main: squash
- main 릴리스 뒤: dev에 main 계보 연결

main은 선형 이력을 유지해요. 릴리스 계보를 연결해야 다음 릴리스에 이미 배포한 변경이 다시 나타나지 않아요.

## 제목과 설명

커밋과 PR 제목은 영어의 type: subject 형식을 사용해요. subject는 소문자로 시작하고 마침표를 붙이지 않아요.

type은 feat·fix·refactor·docs·chore·style·release를 사용해요. 릴리스 노트와 사용자 안내는 한국어로 작성해요. GitHub 릴리스 제목은 vX.Y.Z만 사용해요.

PR에는 바뀐 동작, 실제 실행한 검사, 데이터·운영 영향, 필요한 복구 방법을 적어요. 실행하지 않은 검사를 통과한 것으로 쓰지 않아요.

## 작업과 승인

파일 수정과 Git 기록은 구분해요. 커밋·push·PR 생성·머지·태그·배포는 현재 작업에서 승인된 범위로 진행해요.

혼합 작업트리의 기존 변경을 보존하고 관련 파일이나 변경 구간만 선택해 반영해요.

배포 흐름은 [배포 문서](../technical/deployments.md)를 보세요.
