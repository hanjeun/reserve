# 검색 화면과 헤더

공통 헤더, `/search` 검색 화면, 가게 목록의 배치와 동작이에요.

## 공통 헤더

- PC·모바일 모두 Pretendard·22px·850 굵기·-0.8px 자간의 RESERVE 워드마크를 써요. 로고는 홈으로 이동해요.
- 오른쪽은 검색 아이콘 → 둥근 프로필 사진 순서예요. 검색 아이콘은 `/search`로 가는 링크이고, 헤더에 입력 모양 검색창은 없어요.
- 검색어가 있는 `/stores` 결과에서는 아이콘 대신 현재 검색어를 보여 주는 검색 진입 필드를 둬요.
  - PC: [로고][검색창][계정] 3칸 격자, 필드는 가운데·최대 560px이에요.
  - 768px 미만: 로고를 숨기고 뒤로가기와 검색어 필드만 둬요.
- 검색어가 있는 결과 목록, 상세, 계정 화면에는 PC·모바일 모두 뒤로가기가 있어요. 분야만 선택한 목록은 탐색 루트의 헤더를 유지해요. `useGoBack`으로 이전 화면, 앱 히스토리가 없으면 목록/홈으로 가요.
- 높이는 64px이에요. 검색 아이콘은 44×44px, 로고·프로필·뒤로가기도 44px 높이 동작 영역이에요.
- hover는 중립 opacity, 키보드 포커스는 공통 링이에요.
- 비로그인 `로그인`·`시작하기`는 767px 이하에서 4px 간격·13px 안쪽 여백, 900px 이상에서 두 버튼 사이 12px이에요.
- 로그인 전 프로필 메뉴에는 로그인·회원가입·탐색 링크가 있어요. 보호된 링크는 PrivateRoute를 거쳐요.

## 탐색 탭

- `홈 · 탐색 · 혜택 · 웨이팅 · 피드` 탭은 공통 레이아웃에 한 번 두고, 높이는 44px이에요.
- `/stores` 전체 탐색과 분야 필터 목록은 탭을 유지하고, 검색어가 있는 결과는 탭을 숨겨요. `constants/discovery.js`의 `isDiscoveryRootPath`를 부트 골격과 실제 헤더·본문이 함께 사용해요.
- 혜택은 공개 홍보글을 읽는 소식 목록과 `/benefits/:id` 상세예요.
- 웨이팅은 고객 접수가 가능한 가게 목록이며, 피드는 준비 화면이에요.
- 고정 하단 메뉴는 없고, 법적 고지·문의 푸터는 있어요.

## 검색 화면

- 본문은 최대 960px, 여백은 모바일 20px(아주 좁으면 16px)·태블릿/PC 24px이에요.
- 전역 헤더·탭·푸터를 숨기고 자체 입력·취소 행(64px)을 써요.
- PC 입력은 최대 560px이고, [빈 칸][입력칸][취소] 격자로 가운데에 둬요.
- 입력은 44px 높이/100px 반경 pill, 글꼴 16px, 지우기·취소 동작 영역 44px, 포커스는 중립색 테두리예요.
- 분야 선택은 모바일 3열/2행, 768px 이상 6열/1행이에요. 홈·검색 분야 아이콘은 `constants/discovery.js`의 이미지/광학 크기 정보를 공유해요.
- 빠른 검색 아래에는 이 브라우저의 최근 검색을 보여줘요. 검색어 선택과 개별·전체 삭제를 지원하고, 기록이 없으면 짧은 빈 상태를 표시해요.

## 검색 동작

- 열면 입력에 포커스가 가요. 왼쪽 아이콘은 `type=submit` 버튼이고, Enter·모바일 키보드 검색과 같은 form 제출을 써요.
- 앞뒤 공백을 뺀 검색어로 `/stores?keyword=…`에 가요. 빈 값과 한글 조합 확정 Enter로는 검색하지 않아요.
- 검색 실행·빠른 검색·최근 검색·분야 선택으로 결과에 이동하면 검색 화면의 방문 기록을 교체해요. 결과에서 뒤로가면 검색 전 페이지로 돌아가요.
- 입력 변경만으로 검색 API를 부르지 않아요.
- 지우기는 입력만 비우고 포커스를 유지해요. 취소나 Escape는 헤더로 들어왔으면 이전 화면, 직접 접근했으면 홈으로 가요.
- 빠른 검색 문구는 안내용 예시예요.
- 타이핑 중인 내용은 저장하지 않아요. 실제 실행한 검색만 `localStorage`에 최신순으로 최대 10개·검색어당 100자까지 저장하며 중복을 정리해요. 100자를 넘는 검색도 실행하지만 최근 기록에는 넣지 않아요. 최근 기록 자체를 수집하는 서버 API는 추가하지 않아요.
- 최근 기록은 로그인·로그아웃·계정 또는 세션 전환 시 삭제해요. 다른 계정의 기록을 표시하지 않고 프로필 표시만 바뀌면 유지해요. 개별·전체 삭제는 저장된 목록에도 반영해요. 저장소를 사용할 수 없으면 현재 탭의 메모리만 사용해요.
- `/search`는 `useRouteSeo`의 비색인 기본 정책을 따라요.

## 검색 결과와 가게 목록

- 목록 본문에는 검색 입력이 없어요. 결과 헤더 필드는 현재 검색어를 한 줄로 보여 주고, 누르면 `/search?keyword=…`로 입력을 복원해요. 취소하면 기존 결과의 필터·보기·페이지로 돌아가요.
- 결과 헤더 필드는 링크이고, ‘검색어 수정: …’ 라벨·말줄임·전체 검색어 title이 있어요. 44px 높이·16px 글꼴·최대 560px 폭이에요.
- 목록은 큰 제목 없이 시작해요. 가게 수는 왼쪽, 분야·정렬 메뉴는 오른쪽이에요. 페이지 제목은 화면 낭독기용 `h1`이에요.
- 필터 왼쪽 아이콘으로 사진형(`view=cards`, 원본 비율)과 목록형(`view=list`, 정사각 사진 + 정보)을 전환해요. 아이콘은 다음 보기 모양이에요. 보기만 바꾸면 페이지·필터를 유지하고 API를 다시 부르지 않아요. 조회 중에는 아이콘을 잠가요.
- 결과는 서버에서 12건씩 받고, 하단 AntD 페이지네이션을 써요. 검색·분야·정렬은 URL에 유지하고, 조건이 바뀌면 첫 페이지로 가요.
- 홈·가게 목록의 지역은 같은 브라우저 탭의 `sessionStorage`에 저장해 페이지 이동과 새로고침 후 복원해요. 유효한 URL의 지역을 우선하고, `region=`은 전체 지역을 명시해요. 전체 선택도 저장하며 다른 브라우저 탭에 실시간 전파하지 않아요. 기존 검색·분야·정렬·좌표를 유지하고 실제 지역이 바뀔 때만 첫 페이지로 가요.

## 접근성과 테마

- 검색 입력에 명시적 라벨과 `role=search`, 지우기 버튼에 라벨이 있어요.
- 헤더·탐색 탭·검색 화면의 링크/버튼은 공통 1px 회색 키보드 포커스 링을 써요.
- 분야·정렬 `FilterMenu`는 투명 텍스트 스타일이에요. 보이는 면 32px, 동작 영역 44px, 메뉴는 최소 128px 폭·4px 여백·10px 반경, 항목은 모바일 40px·PC 36px 최소 높이예요. 키보드 포커스에만 링을 둬요.
- 로고의 홈 smooth scroll은 모션 감소 설정을 따라요.
- 시스템 테마가 바뀌면 `useTheme`가 CSS 화면과 AntD 메뉴 algorithm을 함께 바꿔요.

## 페이지 전환

- 검색 화면은 열 때 본문이 올라오고, 취소·Esc로 닫을 때 내려가요. 검색 실행·빠른 검색은 결과를 바로 스켈레톤으로 채우고 옆으로 밀리는 전환을 걸지 않아요.
- `replace` 이동은 전환하지 않아요. 권한·세션 안전장치(남의 예약·변경 불가 예약 → 내 예약, 권한 없음 → 홈, 이미 로그인됨), 소셜 로그인 콜백, 메신저 내부 주소 정리가 여기에 해당해요.
- 사용자가 끝낸 흐름은 호출부가 `reserveRouteMotion`으로 방향을 정해요.

| 이동 | 방향 |
|---|---|
| 로그아웃·탈퇴·회원가입 완료 → 홈 | 왼쪽에서 |
| 로그인 필요 페이지 → 로그인, 비밀번호 변경 → 다시 로그인 | 오른쪽에서 |
| 로그인 성공 → 막혔던 페이지 / 소셜 약관 동의 → 가려던 페이지 | 오른쪽에서 |
| 스스로 로그인 → 있던 페이지, 가려던 곳이 없으면 홈 | 왼쪽에서 |

- 같은 경로 안의 변화(필터·정렬·페이지·지역·보기 방식·패널 탭)는 페이지 진입 전환을 넣지 않아요. 판정은 `routeEntryMotion.js`에서 해요. 선택값 글자는 공통 `RollingFieldValue`로 항목 순서에 따라 위·아래로 움직여요.
- 들어가기와 나가기는 짝을 맞춰요. 메신저 목록 → 대화(오른쪽에서) ↔ 뒤로(오른쪽으로), 광고 신청 다음 단계(오른쪽에서) ↔ 이전 단계(왼쪽에서).
