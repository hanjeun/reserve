# 채팅 입력·설정·전송 취소

기준: 2026-09-27. v2.7.0 후보 코드이며 **운영 배포 완료가 아니다**.

## 사용자 계약

- 고객·사업자·관리자는 같은 입력창을 쓴다. 아래 도구는 사진 첨부와 검색 가능한 Unicode 이모지다.
  일반 문서 업로드·유료 번역·SMS는 포함하지 않는다. 사진은 기존 서버 키 설정이 유효한 환경에서만 표시된다.
- Enter는 전송, Shift+Enter는 줄바꿈이다. 한글 IME 조합 중에는 전송하지 않는다.
- 전송 중 정지 버튼은 브라우저 요청을 중단한다. 서버에 이미 저장됐을 수 있으므로 저장 취소를 보장하지 않는다.
  같은 사진/내용의 재시도는 같은 `clientMessageId`를 사용해 중복 저장을 막는다.
- 보낸 메시지의 관리 메뉴에서 **시간 제한 없이** 전송 취소할 수 있다. 역할만 같다고 취소할 수 없으며
  현재 방 접근권과 실제 발신자 ID가 모두 일치해야 한다. 다른 관리자의 답장도 취소할 수 없다.
  응답에는 발신자 ID를 노출하지 않고 인증된 조회자 기준 `canRetract`만 제공한다.
- 양쪽 일반 화면은 취소 표시를 받고, 일반 사진 조회는 404다. 이미 읽거나 다운로드한 사본은 회수하지 못한다.
  원문·사진은 신고·분쟁 검토용으로 보존하며 권한 있는 신고 컨텍스트에서만 제공한다.
- 오래된 메시지 취소도 `retractionRevision`으로 폴링한다. 새 메시지 ID, 정렬 시각과 읽지 않은 개수를 변경하지 않는다.
- 말풍선 색은 메신저 설정에만 둔다. 설정과 실제 말풍선이 하나의 저장소를 구독하며 **기기별**이다.
  마이페이지에는 앱 전체 모양·글꼴·포인트 색만 남긴다.
  계정 간/다른 기기 간 동기화나 상대방의 색 변경 기능은 아니다. 사이트 전체 브랜드 색을 바꾸지 않는다.
- 기본 배경은 paper 토큰(라이트의 흰색)으로 통일한다. 다크 모드는 같은 토큰을 따르며 하단 내비게이션은 반투명이다.
  들어가기/뒤로가기는 반대 이동 방향과 같은 260ms·가속 곡선을 사용하고 전환 중 재진입을 막는다.
  `reverse` 재생은 가속 곡선까지 뒤집으므로 진입은 별도 keyframe이며, 나가는 목록은 끝에서 투명해진다.
- PC 메시지 관리 메뉴는 내 말풍선 왼쪽에 있고 hover·키보드 포커스 시 보인다. 터치에서는 44px 버튼을 항상 제공한다.
  이모지 창을 열거나 선택할 때 모바일 입력/검색에 강제로 초점을 주지 않는다. 검색을 직접 누르면 키보드가 열린다.
  전송 전 썸네일도 기존 `useImagePreview`를 사용한다. 사진 제거·세션 변경 때 미리보기 Blob을 폐기한다.
  썸네일에 초점이 남아 있어도 Escape는 확대 화면만 닫고 뒤쪽 채팅창은 유지한다.

## 닫기·새로고침

- 모바일 홈·대화 목록·설정·대화 내부에도 44×44px X를 둔다. X는 메시지를 삭제하지 않고
  기존 `/messages` 닫힘 애니메이션 뒤 이전 화면(직접 진입은 홈)으로 돌아간다.
  대화 내부의 ←는 목록으로만 돌아간다. PC 패널의 X와 모바일 X는 같은 디자인 규칙이다.
- 메신저 목록과 공통 `RefreshButton`은 `useRefreshCooldown`의 클릭 후 3초 제한을 공유한다.
  실제 요청 중에는 계속 제한하고 같은 `SyncOutlined`가 회전한다. 요청이 끝난 뒤 남은 쿨다운에는
  회전/`aria-busy`를 표시하지 않는다. 자동 목록 조회는 기존 30초 간격을 유지한다.
- 이것은 브라우저 연타 방지이며 서버 보안 제한이 아니다. 현재 목록 GET에는 전용 Bucket4j 정책이
  없고 저장소 nginx 설정의 API/IP `20r/s`, burst 40 제한이 별도로 있다. 운영 적용 실증과는 구분한다.

## 목록 숨김·신고 증거·90일 파기

### 현재 구현

- 일반 화면은 회색 토큰의 `전송이 취소된 메시지입니다.` 표시를 쓴다. 물리적 삭제를 뜻하지 않으며
  서버의 일반 응답은 원문·사진 주소를 제거한다. 전송 취소는 메시지 행이나 S3 객체를 삭제하지 않는다.
- 가게 대화 참가자는 취소된 상대 메시지도 메뉴에서 `messageId`로 신고할 수 있다. 새 신고는 대상과
  앞뒤 최대 10개씩(대화 신고는 최근 50개)을 `chat_report_evidence`에 접수 시점 그대로 고정한다.
  ADMIN 전용 신고 컨텍스트는 이 스냅샷만 읽는다. 사진은 신고 컨텍스트에 포함된 ID만
  별도 ADMIN 사진 경로로 읽는다. 일반 사진 경로는 관리자라도 취소된 사진을 404로 처리한다.
- 목록 숨김은 MEMBER/OWNER별이며 상대 화면·신고 FK·참가 권한을 삭제하지 않는다. `숨긴 대화 보기`에서
  복원하거나 신고할 수 있다. 새 메시지가 오면 다시 목록에 표시되고, 숨기기만으로 상대를 차단하지 않는다.
  가게 소유자가 변경될 경우 다른 소유자의 숨김을 승계하지 않는다. 관리자 공유 고객지원 받은편지함은 숨기지 않는다.
- 원문·사진의 일반 보존 기간은 **메시지 생성 후 90일**로 정했다. 파기 worker는 메시지 행을 삭제하지 않고
  본문·사진 참조를 비운 뒤 변경 커서로 `보존 기간이 지난 메시지입니다.`를 알린다. 신고 스냅샷에 참조된 사진은
  파기하지 않으며 그 외 사진은 기존 S3 삭제 outbox에 넣는다. 보낸 메시지 재시도 ID는 중복 방지를 위해 남긴다.
- 신고 증거와 열람 기록은 일반 90일 파기 대상에서 제외하며 사용자 결정에 따라 **자동 파기하지 않는다**.
  이 기술 설정이 무기한 보존의 법적 적정성을 확인한 것은 아니다. 보존 목적·접근권·정책 고지와 재검토가 필요하다.
  이전 신고(`evidence_captured_at` NULL)는 스냅샷 고정 전까지 해당 방의 파기를 보류한다.
- `CHAT_RETENTION_ENABLED` 기본값은 false다. 추가 DDL·개인정보 고지·기존 데이터 영향·복구 호환 검증 전에는
  운영 파기를 켜지 않는다. 기존 백업/스냅샷 복사본의 보존 기간은 별도이며 새 비용성 인프라는 만들지 않는다.
- 관리자 원문·사진 조회는 `chat_report_access_audit`에 관리자 ID·사건 ID·대상 ID·UTC 시각·행동·목적
  (`REPORT_REVIEW`)을 별도 트랜잭션으로 기록한다. 감사 저장 실패 시 원문 응답도 실패하며 원문은 로그에 넣지 않는다.
  DB 관리자 자체 접근까지 감사/변조 방지가 완성된 것으로 표현하지 않는다.
- 사진 S3 객체는 암호화되지만 텍스트 DB 원문의 별도 암호화는 현재 계약이 아니다.
  DB 접근 제한과 관리자 신고 경로 제한을 원문 전체 암호화로 표현하지 않는다.

### 남은 정책·후속 범위

1. 고객지원(SUPPORT) 신고, 과거 가게 소유권 이력 기반 접근권, 사건별 보류 해제·증거 파기·열람 원장 조회 UI.
2. 사진의 GCM 무결성 검증 외 별도 원본 해시/서명 및 DB 운영자 변조 방지 저장소는 아직 없다.
3. 카카오톡식 메시지별 `1`은 미구현이다. 현재 방 단위 unread 합계를 각 메시지에 복사하지 않는다.
   상대 마지막 읽음 메시지 ID를 서버에 기록하고 폴링으로 반영해야 하며 고객지원 다중 관리자 읽음 규칙도 필요하다.

## API와 추가 DDL

| 대상 | 계약 |
|---|---|
| `POST /api/chat/rooms/{roomId}/messages/{messageId}/retract` | 인증·방 접근·실제 발신자 확인, 멱등 취소, 전송 limiter 적용 |
| `GET /api/chat/rooms/{roomId}/retractions?afterRevision=0` | 인증·방 접근 확인, 최대 100개, `messages/nextRevision/hasMore` |
| `chat_room.retraction_revision` | BIGINT NOT NULL DEFAULT 0 |
| `chat_message.retracted_at` | DATETIME(6) NULL |
| `chat_message.retraction_revision` | BIGINT NULL; `(room_id,retraction_revision)` 인덱스 |
| `PUT /api/chat/rooms/{roomId}/visibility?viewerRole=MEMBER&hidden=true` | 본인 참가 축의 목록 숨김·복원, 방 잠금, 원장 삭제 아님 |
| `GET /api/chat/conversations` / `/store-inbox`의 `hidden=true` | 숨긴 목록 서버 pagination, 기존 기본값 false |
| `chat_room.member_hidden_at` / `owner_hidden_at` / `owner_hidden_by_member_id` | nullable DATETIME(6) / DATETIME(6) / BIGINT |
| `chat_message.purged_at` | nullable DATETIME(6), `(purged_at,created_at,id)` 인덱스 |
| `chat_report.evidence_captured_at` | nullable DATETIME(6), 이전 신고 파기 보류 표식 |
| `chat_report_evidence` / `chat_report_access_audit` | 신고 스냅샷 / 원문 접근 감사, 일반 API에 노출하지 않음 |

방을 먼저 `FOR UPDATE`로 잠근 뒤 권한을 확인하고 커서를 읽는다. 읽기 조회로 먼저 로드한 오래된
managed entity를 재사용해 동시 취소의 커서가 겹치는 것을 방지한다.
