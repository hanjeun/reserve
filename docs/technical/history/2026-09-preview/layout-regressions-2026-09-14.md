# 배너·확인 모달·모바일 가게 폼 회귀 보정

2026-09-14 KST, `local-preview-all-changes`의 미커밋 프리뷰 기준이다. 기존 변경을 보존하고
사용자가 지적한 세 가지 레이아웃 문제만 보정했다. 운영 배포 결과나 전체 화면의 완료 선언이 아니다.

## 확인한 원인과 변경

### 홈 배너

실제 비로그인 홈에서 누르는 동안 첫 배너의 `scale(.97)`을 확인했다. 원래 350.4px인 배너가
339.9px로 줄었다. 옆 배너에는 transform이 없었지만 x 좌표가 380.4px에서 374.8px로 이동했다.
트랙 자체의 transform은 없었다. 이웃까지 축소된 것이 아니라, 눌린 배너의 크기 변화와 브라우저의
포커스/scroll-snap 위치 보정이 함께 보이는 것으로 판단했다.

`feature-surfaces.css`에서 홈 배너만 크기 변화 없는 투명도 피드백으로 옮겼다. 수정 후 누르는 동안
첫/다음 배너의 너비 350.4px, x 좌표 20/380.4px, 트랙 scrollLeft 0이 유지되었다.
다음 버튼을 누르면 번호가 2/3으로 바뀌고 scrollLeft 360.8px로 이동하는 기존 동작도 확인했다.
3D 바로가기·작은 사진의 눌림은 보존했다. 원본 사진·비율·번호 표시의 디자인은 바꾸지 않았다.
번호 리디자인은 [기존 계획 §9](design-evolution-plan-2026-09-13.md)의 계획 항목으로 남는다.

### 모바일 가게 등록·수정

단순히 글자만 큰 문제가 아니었다. 공통 `PageContainer`의 `width: 100%`에 좌우 패딩이
content-box로 더해져 390px 기기에서 실제 폼 폭이 422.4px가 되었다. 문서 너비가 32px 넘치고
visual viewport scale이 약 0.924로 축소되었다. 공통 관문에 `boxSizing: 'border-box'`를 추가해
패딩을 전체 너비 안에 포함했다. 수정 후 같은 기기에서 가로 넘침 0, scale 1을 확인했다.

또한 AntD `Form size=large`의 기본 규칙이 세로 폼 라벨에도 40px 높이를 남기고 있었다.
등록·수정 폼 클래스와 모바일 미디어 쿼리 안에서만 라벨을 자동 높이·최소 22px로 바꿨다.
측정한 단일 라벨/입력 행은 라벨 40→22px, 전체 행 92→74px가 되었다.

같은 `StoreForm`을 사용하는 등록과 수정에 다음 밀도를 적용했다.

- 768px 미만: 입력·Select·날짜·시간·주소·하단 액션 44px, 모서리 10px, 필드 간격 12px,
  라벨 아래 8px, 페이지 패딩 위20/좌우16/아래40px, 제목24/설명14px.
- AntD 6 Select의 높이 변수뿐 아니라 실제 16px 글자의 24px 줄 높이도 변수에 맞췄다.
  height만 덮거나 사라진 v5 `.ant-select-selector`를 사용하지 않는다.
- 짧은 환불·마감 필드만 두 칸으로 묶었다. 시간 범위·긴 도움말은 좁은 두 칸에 넣지 않는다.
  모바일 옵션 설명과 스위치는 설명 왼쪽/스위치 오른쪽으로 정렬한다. textarea는 44px 고정 대상이 아니다.
- 768–899px: 최대700px, 주요 정보는 한 열. 900px 이상: 기존 최대1000px·주요 두 열.
  두 열을 다시 잘게 나누면 시간이 좁아지는 900–1023px 구간에서만 시간 범위 행을 세로로 배치한다.
  1024px 이상은 기존 시간 범위 가로 배치를 유지한다.
- 기존 Core 입력의 명목 높이54px와 폼/날짜/오류/선택 계약은 유지했다. 실제 PC Select는 기존 계산상
  53px로 측정되었으며 이 배치에서 Core 전체의 1px 차이를 변경하지 않았다.
- 가게 수정 최초 조회 스켈레톤도 모바일44px·필드12px·라벨8px·좌우16px의 같은 밀도를 사용한다.

필드명·옵션·초기값·검증·`onFinish`·`onValuesChange`·임시저장/제출 분리·대기 중 비활성 조건을
보존했다. `StoreRegister`/`StoreEdit`의 API·소유권·임시저장 훅은 변경하지 않았다.

### 확인/탈퇴 모달

실제 계정 화면에서 지속적으로 완전히 보이지 않는 현상은 이번에 재현하지 못했다.
직접 숨기는 규칙이 원인이라고 확정하지 않는다. 대신 공통 `useMessage.confirm`에
`reserve-confirm-root` 관문을 추가하고, 실제 AntD 6 포털 구조에서 좁은 화면·긴 본문을 보강했다.

패널은 좌우16px과 safe-area를 확보하고 높이는 `100svh` 범위로 제한한다. 본문만 내부 스크롤하며
버튼 행은 스크롤과 분리하고 최소44px로 둔다. 기존 문장 단위 줄 나눔, 호출부의 rootClassName,
옵션·콜백·danger·disabled는 보존했다. AntD mask·focus·열림/닫힘 애니메이션을 강제로 지우지 않는다.

MyPage의 탈퇴 가능 여부 조회, 예약·환불·가게 등 탈퇴 차단 조건, `deleteMember`/로그아웃/이동과
실제 `onOk`는 수정하지 않았다. 검증 중 탈퇴하기는 누르지 않았다.

## 실행한 검사와 경계

- 최종 명시7파일 단일 실행29테스트 통과: Home6, 배너 CSS2, PageContainer2, StoreFormLayout10,
  useMessage5, useStoreForm2, lifecycleReadiness2. 전체 frontend suite는 실행하지 않았다.
- 변경11개 JS/JSX 파일 ESLint 통과. CSS9파일897규칙 PostCSS 파싱 및 잘못된 한국어 선택자 검사 통과.
- 최종 Vite production build와 번들 예산 검사 통과: 초기 JS321.0KiB gzip, 최대 JS563.7KiB.
  `npm`의 sitemap prebuild 전체 워크플로가 아니라 Vite 직접 빌드와 별도 예산 검사다.
- 변경 경로의 `git diff --check`와 새 기록/캡처 안내의 로컬 링크13개 검사 통과.
  독립 읽기 전용 검토에서도 지정 범위의 높은 확률 신규 회귀는 발견하지 못했다.
- 기존108개 소스 동결 ZIP의 SHA-256은
  `02d5809dabf319ed1778140210e4303862b5f5a37b0b5ef6dd5d880514af536e`로 유지됨을 다시 확인했다.
  신규 프로젝트용 기준선을 덮어쓰거나 Core를 일괄 교체하지 않았다.
- 검증용 device metrics/viewport를 복원하고 이번 작업에서 만든 두 탭을 닫았다. 기존 사용자 탭은 유지했다.
- 실제 계정 탈퇴, 로그인, 위치 권한, 가게 등록·저장·수정·업로드, 알림 발송은 하지 않았다.
  backend 전체 검사·운영 DB/브라우저 통합·배포는 실행하지 않았다.
- 커밋·스테이징·브랜치 이동·PR·push·태그·배포·서버/AWS 변경은 하지 않았다.

기초 레이아웃 안정화를 먼저 하고, 소식/혜택·상세/내 예약·웨이팅/피드는
[기존 전환 순서](design-evolution-plan-2026-09-13.md)를 유지한다. 모달의 실제 계정 화면에서만 남는
현상이 있으면 계정 동작을 실행하지 않고 열린 상태의 DOM·스타일·오류부터 추가 확인한다.
