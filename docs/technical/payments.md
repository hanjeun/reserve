# 예약금과 환불

예약금 결제와 환불은 PortOne의 실제 처리 결과를 확인해 반영해요.

## 결제 흐름

1. 서버가 예약과 결제 금액을 확인하고 결제 시도를 만들어요.
2. 사용자가 결제창에서 결제해요.
3. 서버가 결제사의 주문·금액·상태를 확인해요.
4. 결제 기록과 예약의 결제 여부를 함께 반영해요.

화면의 완료 표시나 외부 알림만으로 결제 성공을 확정하지 않아요. 같은 요청이 반복돼도 결제 결과가 중복 반영되지 않도록 처리해요.

## 결제 상태

| 상태 | 의미 |
|---|---|
| READY | 결제 준비 |
| PAID | 결제 완료 |
| CANCELLED | 결제 취소 |
| REFUND_PENDING | 환불 결과 확인 중 |
| REFUNDED | 환불 완료 |
| PARTIAL_REFUNDED | 부분 환불 완료 |
| FAILED | 결제 실패 |

결제할 금액은 예약 당시 저장한 값을 사용해요. 미결제 자동 만료는 예약 상태와 결제 마감 설정을 함께 확인해요.

## 환불

취소·거절 결정과 환불 요청 기록을 먼저 함께 저장해요. 결제사 호출은 데이터베이스 잠금 밖에서 수행하고, 확인된 결과를 별도 처리해요.

- 이미 환불한 금액을 다시 요청하지 않아요.
- 요청 금액·실제 취소 금액·개별 취소 기록을 대조해요.
- 결과가 불명확하면 성공이나 실패로 추측하지 않고 다시 확인할 대상으로 남겨요.
- 환불이 확정되면 결제 기록과 예약의 결제 표시를 함께 바꿔요.

## 웹훅과 재확인

결제사가 보내는 웹훅은 서명을 검사하고 먼저 저장한 뒤 처리해요. 일시 실패한 알림과 오래 멈춘 결제는 재확인할 수 있어요.

자동 재시도와 관리자의 조회는 실제 결제·환불 실행과 구분해요.

## 관련 코드

backend의 payment 영역에서 결제·환불·웹훅을 처리해요. 광고는 [광고 결제](ad-payments.md), 거래가 남아 있을 때의 탈퇴·폐업 제한은 [데이터 보관과 삭제](data-lifecycle.md)를 보세요.
