# 계정 보안

회원 인증, 비밀번호, 소셜 계정 연결을 보호하는 규칙이에요.

## 로그인

- 이메일·비밀번호와 Google·Kakao·Naver 소셜 로그인을 지원해요.
- access token은 API 인증에, refresh token은 로그인 유지에 사용해요.
- 서버는 토큰의 서명·발급자·용도·만료와 현재 회원 상태를 확인해요.
- 비밀번호 변경·탈퇴·계정 상태 변경 뒤에는 이전 인증으로 접근할 수 없도록 처리해요.

## 비밀번호와 이메일 인증

| 항목 | 기준 |
|---|---|
| 비밀번호 | 8~64자, 영문과 숫자 포함, UTF-8 72바이트 이하 |
| 저장 | bcrypt 해시 |
| 유출 비밀번호 | 알려진 유출 목록과 대조해 거부 |
| 이메일 인증 | 만료시간·시도 제한·인증 목적 확인 |

가입과 비밀번호 재설정은 각 목적에 맞는 인증을 거쳐요. 인증 코드와 가입 증명은 URL이나 브라우저 저장소에 남기지 않아요.

## 소셜 계정

공급자 토큰은 서버의 독립된 키로 암호화해요. 탈퇴 후 연결 해제는 저장된 작업으로 재시도하며, 완료한 토큰은 제거해요.

공급자의 계정 변경 알림은 서명·발급자·대상·사건 종류를 확인해 처리해요. 로그인 콜백과 다른 경로를 사용하고, 별도 설정으로 활성화해요.

## 설정과 코드

암호화 키와 소셜 로그인 비밀 값은 서버 환경에만 두어요. 로그인 토큰·공급자 토큰·재시도 작업은 용도에 맞는 별도 키를 사용해요.

인증은 backend의 config·member·email 영역, 연결 해제와 파일 삭제는 [데이터 보관과 삭제](data-lifecycle.md)를 보세요.
